# migrations: Guardrails

## First migration

- `0001_initial_schema.sql` is the main manager schema at the point `v2` was created (commit `4829aed7fe`). The alembic head is `ae624fa26235`, and it was created with `mgr schema oneshot`.
- There is no `alembic_version` table.
- Do not edit this file. Add a schema change as a new file.

## Files and the order they apply

- A migration is a `*.sql` file in this directory. The file name follows `0001_initial_schema.sql` (a four-digit number, an underscore, a name).
- Files apply in file name order.
- `migrations.go` binds the files into `migrations.Files` (`embed.FS`) with `//go:embed *.sql`. Do not put a migration file outside this directory.
- `internal/dbtest` applies `migrations.Files` in name order to build the template database. The file names and contents set the template name, so the template is built again when a file changes.
- Each file runs as one simple-protocol query.

The SQL rules (no `SELECT *`, no `INSERT` without a column list, no `COPY`) and the ban on an alembic migration on main are in the root `AGENTS.md`.

## Why the SQL rules

A first-install database (`0001_initial_schema.sql`) and an existing database upgraded with alembic differ in column order in 5 tables (schema comparison on 2026-11-26, no other difference).
