## 26.9.0a1 (2026-09-16)

### Breaking Changes
* Allow deployment revision presets to omit model `name`, `model_path`, and service `port` so revisions inherit merge-chain defaults at resolution, moving the preset GraphQL `model_definition` input/output to sparse `PresetModelDefinitionInput`/`PresetModelDefinition` types ([#13536](https://github.com/lablup/backend.ai/issues/13536))
* Switch Prometheus query preset templates to `${{labels}}`, `${{window}}` and `${{group_by}}` placeholders — every other character is literal PromQL — and migrate stored presets automatically; the legacy `str.format` placeholder syntax is no longer accepted ([#13675](https://github.com/lablup/backend.ai/issues/13675))
* Carry event payloads as JSON instead of msgpack; all cluster components must run the same version across this upgrade ([#13746](https://github.com/lablup/backend.ai/issues/13746))
* Remove the `HiRedisQueue` message queue implementation and the `use-experimental-redis-event-dispatcher` config field from the manager, agent, storage-proxy, app-proxy-coordinator and app-proxy-worker — `RedisQueue` is now the only transport. A config file that still sets the option keeps loading, with the option ignored. ([#13747](https://github.com/lablup/backend.ai/issues/13747))
* Purging a resource group no longer removes the sessions, kernels, endpoints and routings it holds; remove them before purging. ([#13920](https://github.com/lablup/backend.ai/issues/13920))
* Remove role invitations, including the `/v2/role-invitations` REST routes, their GraphQL queries and mutations, the SDK client, the CLI commands, and the `role_invitations` table. ([#13981](https://github.com/lablup/backend.ai/issues/13981))
* Count API requests in a per-user fixed window (one hash per user) instead of a sorted set member per request, so rate limit memory no longer grows with request volume, and add the X-RateLimit-Reset header. ([#14211](https://github.com/lablup/backend.ai/issues/14211))
* Require permission on the named entity to read a resource group's scheduling fit, a domain, or the cluster's total agent capacity, so these reads answer a superadmin only until role templates grant them. ([#14299](https://github.com/lablup/backend.ai/issues/14299))
* Bind each role to exactly one scope, recorded on the role itself, so that leaving a project takes back only the roles that project holds, and require that single scope when creating a role, which no longer accepts a source. ([#14445](https://github.com/lablup/backend.ai/issues/14445))
* A permission row no longer carries a scope: the role it belongs to places every grant, and `scopeType` / `entityType` on the RBAC API carry the entity type name instead of the `RBACElementType` enum. ([#14469](https://github.com/lablup/backend.ai/issues/14469))
* Report a manager error about an entity or a field row under that row's own type instead of a fixed error domain, so a missing row answers with a code naming what was missing. ([#14471](https://github.com/lablup/backend.ai/issues/14471))
* Answer the scope-entity relation from the virtual entity graph alone and drop the `association_scopes_entities` table, removing the listings that read the relation directly: the GraphQL `adminEntities` query, `Role.scopes` and the `EntityRef` types, the REST v1 and v2 entity search endpoints, and the `rbac.search_entities` SDK call with its `bai rbac entity search` command ([#14478](https://github.com/lablup/backend.ai/issues/14478))
* Name a permission by its bit alone: `operation` on the RBAC permission and role-preset APIs becomes `permission`, carrying `read` / `update` / `create` / `soft_delete` / `hard_delete`, and the `grant:*` operations are gone. `CreatePermissionRequest` no longer takes a scope, `object_permissions` is dropped, and the RBAC entity and operation listings answer from the wired operations rather than a hand-kept table. ([#14494](https://github.com/lablup/backend.ai/issues/14494))
