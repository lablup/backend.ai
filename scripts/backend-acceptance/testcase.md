# 백엔드 인수 테스트 — 명세

컨테이너 백엔드(`containerd` / `enroot` / `singularity`) **하나**를 실제 배포에 올렸을 때
"쓸 수 있는 상태인가"를 판정하는 케이스 명세다. 각 케이스는 **무엇을 하고, 무엇이 참이어야 하는가**만
적는다. 실행 결과는 여기 두지 않는다 — `results/` 를 보라.

## 전제

| 항목 | 내용 |
|---|---|
| **한 번에 한 백엔드** | 검사 대상 백엔드만 두 노드에서 띄운다. 여러 백엔드가 동시에 뜨면 LOCAL 블록·RPC 포트·cgroup이 얽혀 어느 쪽 문제인지 판별할 수 없다 |
| 노드 2개 | 멀티노드 케이스에 필요. `ACC_PEER_HOST` 가 없으면 해당 케이스는 SKIP |
| 실행 위치 | 로컬 노드. 원격 노드에는 SSH 무암호 접근 |
| 권한 | `sudo -n` (netns 진입, cgroup·로그 확인) |

```bash
export ACC_IMAGE_ID=...  ACC_PROJECT_ID=...    # 필수
export ACC_PEER_HOST=192.168.0.156             # 없으면 멀티노드 케이스 SKIP
export ACC_START_CMD='...'                     # G2·G3 (에이전트 재기동)에만 필요

./run.sh cd            # containerd 전체
./run.sh en B2 C1 F3   # enroot 특정 케이스만
./run.sh --list
```

케이스는 상태를 물려받는다 — B2가 띄운 멀티노드 세션을 C1·C2가 그대로 쓴다. 개별 실행도 되며,
그때는 필요한 세션을 해당 케이스가 직접 띄운다.

---

## A. 기동

### A1 — 대상 백엔드만 두 노드에서 기동
**한다**: 매니저의 ALIVE 에이전트 목록과, 두 노드에서 백엔드별 RPC 포트(cd 6211 / en 6011 / sg 6111)의 리스닝 여부를 확인한다.
**기대**: 대상 백엔드의 에이전트가 두 노드 모두 ALIVE이고, **다른 백엔드의 RPC 포트는 어느 노드에서도 열려 있지 않다.**
**막는 것**: 여러 백엔드가 같은 노드의 LOCAL 블록·cgroup·포트를 두고 경합하는 상태에서 검사하는 것.

### A2 — privnet (rootless 전용)
**한다**: `network-privnet-socket` 이 가리키는 경로에 유닉스 소켓이 있는지, privnet 프로세스가 있는지 본다.
**기대**: 소켓이 설정된 경로에 존재하고 프로세스가 살아 있다.
**막는 것**: 설정 누락으로 privnet이 기본 경로에 붙어 에이전트가 연결하지 못하는 상태.
**해당 없음**: containerd (privnet은 선택 사항).

---

## B. 세션 수명주기

### B1 — 단일노드 세션
**한다**: 로컬 에이전트에 고정한 4 CPU / 2 GiB 세션을 띄운다.
**기대**: RUNNING 도달.

### B2 — 멀티노드 세션과 실제 분산
**한다**: 로컬 노드의 **실제 여유 CPU에서 계산한** filler를 먼저 띄워 8 CPU 커널 하나만 들어가게 만든 뒤, `cluster_size 2` 세션을 띄운다. 그리고 커널이 어느 에이전트에 배치됐는지 조회한다.
**기대**: RUNNING이고, **두 커널이 서로 다른 노드에 있다.**
**막는 것**: 자원이 한 노드에 다 들어가면 스케줄러가 담는다. 배치를 확인하지 않으면 단일노드 성공을 멀티노드 성공으로 오독한다. `agent_list` 핀만으로는 분산이 강제되지 않는다.

### B3 — 연속 기동
**한다**: B2와 같은 세션을 `ACC_CHURN`회(기본 5) 반복하며, 매회 `ACC_CHURN_GAP`초(기본 12) 간격으로 띄우고 종료한다.
**기대**: 전 회차 RUNNING이고 전 회차 분산.
**막는 것**: 빠른 회전에서만 드러나는 실패. 1~2회로는 보이지 않는다.

### B4 — 종료 후 잔여물
**한다**: 이 스위트가 띄운 세션을 모두 종료하고, 두 노드의 잔여 REPL 소켓 수와 종료된 커널의 로그 파일 수를 센다.
**기대**: 잔여 REPL 소켓 0(양 노드), 종료된 커널의 로그 파일 0.

## C. 네트워크 (컨테이너 안에서)

> 두 케이스 모두 컨테이너의 netns 안에서 확인한다. 호스트에서 재면 의미가 없다.

### C1 — 클러스터 DNS
**한다**: main1 커널의 netns에서 기본 게이트웨이를 DNS 서버로 삼아 `sub1`과 `main1`을 조회한다.
**기대**: 두 이름 모두 주소를 돌려준다.

### C2 — 노드 간 L3
**한다**: C1이 받은 **오버레이 주소**로 main1→sub1, sub1→main1 각각 3회 ping.
**기대**: 양방향 모두 0% 손실.
**주의**: LOCAL 주소(`172.30.x`)는 노드마다 같은 값이라 그것으로 ping하면 **자기 자신**을 친다. 반드시 DNS가 돌려준 주소를 쓴다.

## D. 격리

### D1 — seccomp
**한다**: 커널 프로세스(`init.py`)와 그 **자손**(PPid를 타고 확인)의 `/proc/<pid>/status` 에서 `Seccomp` 값을 읽는다.
**기대**: 커널과 모든 자손이 `Seccomp: 2`(filter).
**주의**: 런타임 자신의 발판(apptainer `starter`/`appinit`, enroot `enroot-nsenter`)은 필터 밖이며 정상이다. 커널 프로세스를 정확히 짚어야 한다 — 그 발판의 argv에는 커널 엔트리포인트 경로가 들어 있어 문자열 매칭으로는 구분되지 않는다.

### D2 — cgroup 한도
**한다**: `/sys/fs/cgroup/backend-ai/<kernel-id>/` 의 `memory.max`, `cpuset.cpus` 를 읽는다.
**기대**: 세션이 요청한 값과 일치(이 스위트 기준 `memory.max=2147483648`, cpuset은 4개).
**막는 것**: 위임이 실패하면 `memory.max = max`, 전체 CPU 허용 상태로 조용히 실행된다.

### D3 — cgroup 위임 실패 (rootless, 수동)
**한다**: privnet을 `cap_dac_override` 없이 띄워(응답은 하지만 `/sys/fs/cgroup` 에 mkdir 불가) 세션을 요청한다.
**기대**: 커널이 **거부**되고 세션이 실패하며, 저널·로그·스크래치·cgroup 잔여가 0이다.
**비고**: 자동화하려면 privnet 기동 방식을 스위트가 알아야 하므로 현재는 수동 절차다.

### D4 — 커널의 cgroup 위치
**한다**: 커널과 에이전트의 `/proc/<pid>/cgroup` 을 비교한다.
**기대**: 커널의 cgroup이 **에이전트의 cgroup 하위가 아니다.**
**막는 것**: setsid는 프로세스 그룹만 바꾼다. systemd의 기본 `KillMode=control-group` 은 cgroup 단위로 죽이므로, 커널이 에이전트 cgroup 안에 있으면 `systemctl stop` 에 함께 죽는다.

## E. 스탯

### E1 — per-container 지표
**한다**: 에이전트의 `/metrics`(cd 6203 / en 6003 / sg 6103)에서 해당 커널의 `backendai_container_utilization` 시계열을 수집한다. 수집기는 주기로 돌므로 최대 90초 기다린다.
**기대**: `mem`, `io_read`, `net_rx`, `net_tx`, `cpu_used` 가 모두 존재한다.

### E2 — 매니저 반영
**한다**: 매니저에서 해당 에이전트의 `occupied_slots` 를 조회한다.
**기대**: 이 세션의 할당(4 CPU)이 반영돼 있다.
**주의**: 에이전트 총량은 그 노드의 모든 커널 합이다. 다른 세션이 있으면 값이 커지므로 등호로 판정하지 않는다.

## F. 로그

### F1 — 캡
**한다**: 커널의 stdout으로 48 MiB를 흘린 뒤 로그 파일 수와 개별 크기를 센다.
**기대**: 파일 ≤5개, 개당 ≤ `container_logs.max_length / 5`(기본 2 MiB).

### F2 — 지속 부하 피크 (수동)
**한다**: 일정 속도(예: 5 MiB/s)로 일정 시간 쓰면서 디스크 점유 피크를 표본한다.
**기대**: containerd는 예산 이내(하드 캡). rootless는 `4 × max_size + 쓰기속도 × 5초` 이내(소프트 캡).

### F3 — 로테이션 가로질러 읽기
**한다**: F1으로 회전이 일어난 뒤 `bai session logs` 로 읽는다.
**기대**: 회전된 파일까지 포함해 1 MB를 크게 넘는 양이 돌아온다(활성 파일만 읽으면 거의 비어 있다).

### F4 — 무손실 (하드 캡 백엔드, 수동)
**한다**: 유지 구간(기본 8 MiB) 안에 들어가는 분량의 **번호 매긴 줄**을 흘린 뒤 전 파일을 이어 읽는다.
**기대**: 결번 없음.

### F5 — 종료 시 삭제
**한다**: 세션 종료 후 해당 커널의 `.log` 와 회전분을 센다.
**기대**: 0개.

### F6 — 로그 라이터 실패 (containerd)
**한다**: 커널이 RUNNING인 상태에서 활성 로그 파일의 존재를 확인한다.
**기대**: 파일이 **반드시 존재**한다.
**막는 것**: `binary://` 라이터가 뜨지 못하면 커널은 RUNNING인데 출력이 전부 버려진다. 라이터는 containerd가 task를 놓아주기 전에 이 파일을 만들므로, 파일 없음은 곧 라이터가 안 떴다는 뜻이다.

## G. 복구

### G1 — 에이전트 SIGKILL
**한다**: 커널이 도는 상태에서 에이전트를 SIGKILL 한다.
**기대**: 커널 프로세스가 살아 있다.

### G2 — 재기동
**한다**: `ACC_START_CMD` 로 에이전트를 다시 띄운다.
**기대**: 세션이 여전히 RUNNING이고 커널이 살아 있다.

### G3 — 고아 정리와 보존
**한다**: 존재하지 않는 커널 id의 로그 파일과 스크래치 디렉터리를 심어 두고, **살아있는 커널을 하나 둔 채** 에이전트를 재기동한다.
**기대**: 심어 둔 고아 둘은 제거되고, **살아있는 커널의 로그는 남아 있다.**
**주의**: 스크래치는 커널의 `/home/work` 다. "지워졌나"만 보면 안 되고 "살아있는 것이 남아있나"를 반드시 함께 본다.

### G4 — PID 1 좀비 수거
**한다**: 컨테이너 안에서 고아 프로세스 50개를 만들고 잠시 뒤 좀비 수를 센다.
**기대**: 0개.

## 케이스를 더할 때

1. **결과가 아니라 상태를 본다.** "RUNNING"만으로는 부족하다. 커널이 어느 노드에 갔는지, cgroup에 값이 들어갔는지, 로그 파일이 생겼는지를 확인한다.
2. **살려두는 쪽도 검사한다.** 정리 케이스는 "지워졌나"와 "살아있는 것이 남아있나"를 같이 본다.
3. **한 번으로 판정하지 않는다.** 간헐적 실패는 반복에서만 나온다.
