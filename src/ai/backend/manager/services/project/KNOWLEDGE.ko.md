# 프로젝트 service

프로젝트는 도메인 아래에 속하므로 생성은 도메인을 스코프로 하는 scope 모양이고, 기존
프로젝트를 지정하는 연산은 single-entity 모양이다.

## processor 구성

`backend.ai mgr ops list --concern organization --entity project` 는 연결된 목록을
출력한다. 그 출력이 엔티티 타입, 모양, 연산, gate, backing 을 나타낸다.

## 개인 프로젝트

`ProjectType.PERSONAL` 은 동작을 두 곳에서 변경한다. 나머지는 일반 프로젝트와 같다.

| 위치 | 동작 |
|---|---|
| 멤버 추가 | 네 경로 모두 거부한다: 프로젝트 멤버 update(add), 사용자 배정, 사용자 binding, 사용자 생성이나 수정이 실행하는 프로젝트 sync |
| 삭제와 purge | 자체적으로 거부한다. 개인 프로젝트는 그 사용자와 함께 사라진다 |

사용자 수정 시 실행하는 프로젝트 sync 는 두 집합 모두에서 개인 프로젝트를 뺀다. 대상
집합에서 빼는 것만으로는 부족하다. 현재 집합에서도 빠져야 하며, 그렇지 않으면 sync 가
사용자를 자기 개인 프로젝트에서 분리한다.

목록 조회는 타입으로 필터하지 않는다. legacy group 질의는 이미 `type=[GENERAL]` 기본값으로
개인 프로젝트를 빼고, v2 search 는 스코프와 권한만으로 판정한다. 도메인 search 는 그
도메인에 속하고 호출자가 접근할 수 있는 프로젝트를 반환하므로, 개인 프로젝트는 소유자와
도메인 관리자에게 보인다.

사용량 질의는 개인 프로젝트를 빼지 않는다. 그 세션이 실제 자원을 소비하므로 빼면 설치 전체
합계가 틀리고, 두 사용량 endpoint 모두 프로젝트를 지정할 수 있는데 그러면 빈 결과를
응답하게 된다.
