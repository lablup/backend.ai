# User service: 배경

사용자는 도메인 아래에 있으므로 생성은 도메인을 스코프로 하는 scope shape 이고, 기존 사용자를 지정하는 operation 은 single-entity 다. keypair 는 사용자의 field row 이므로 keypair 에 대한 모든 operation 은 own 하는 사용자가 처리한다.

## keypair operation 의 shape

keypair row 는 자체 소속을 갖지 않는다. access key 로 keypair 를 지정하는 요청은 key owner lookup 으로 own 하는 사용자를 먼저 조회하고, 이어지는 operation 이 그 사용자를 지정한다. 모든 쓰기는 UPDATE 다. keypair row 를 추가하거나 제거하는 일은 그 사용자에 대한 변경이다.

## Bootstrap script 와 dotfile

- `bootstrap_scripts` 는 `(entity_type, entity_id)` 마다 script 를 담는다. `user_default_bootstrap_scripts` 는 사용자의 기본 script 를 참조하고, 사용자당 0개 또는 1개다.
- script 내용은 `bootstrap_script_revisions` 에 있고, 이 테이블은 row 만 추가한다. update 는 요청한 사용자를 `creator_id` 로 하여 다음 `revision_number` 를 추가하고, 최신 revision 이 현재 내용이다.
- legacy API 와 세션 생성은 사용자의 삭제되지 않은 기본 script 의 최신 revision 을 사용한다. 기본 script 가 없으면 조회는 빈 script 를 반환하고 legacy update 는 script 를 생성해 기본으로 지정한다.
- v2 세션 생성은 script 가 없는 요청을 사용자의 기본 script 로 채우고, 그다음 자원 그룹의 기본 execution spec 으로 채운다.
- `processors.bootstrap_script` 에서 script 를 id 로 지정하는 operation 인 get, bulk get, add revision, purge 는 dangling lookup field 그룹에 있다. owner lookup 이 row 의 `entity_type` 으로 script 소유자를 찾고, 그 script 소유자가 operation 을 처리한다. 소유자를 이름으로 받는 operation 은 사용자 single-entity action 인 create, switch default, unset default 와 사용자 scope search 다. script row 에는 내용이 없다. `bulk_get_current_revisions` 가 같은 owner lookup 으로 지정한 script 마다 가장 마지막 revision 을 읽는다. 이 operation 은 data 가 revision 인 두 번째 그룹에 있다. 삭제된 script 도 삭제되지 않은 script 와 같이 조회하고 영구 삭제한다. switch-default 와 add-revision 은 삭제된 script 에 대해 찾을 수 없음으로 응답한다.

| Operation | 규칙 | 이유 |
|---|---|---|
| create | 항상 non-default 이고 같은 트랜잭션에서 revision 1 을 생성한다 | 기본은 switch-default 로만 옮긴다 |
| add-revision | 기본 여부와 관계없이 삭제되지 않은 script 에 다음 revision 을 추가한다. creator 의 전제 조건이 삭제된 script 를 거부한다 | revision 은 row 만 추가한다 |
| switch-default | 사용자의 지정 row 를 그 사용자에 설정된 삭제되지 않은 script 로 업서트한다 | 사용자당 지정 row 는 하나다 |
| purge | 기본으로 지정된 script 는 거부한다. 그 revision 은 cascade 로 함께 삭제된다 | 기본 keypair 와 같다. 기본을 먼저 전환한다 |
| unset default | 지정 row 를 삭제하고 script 는 남긴다 | 사용자에게 기본 script 가 없을 수 있다 |

- `auto_generated_files` 는 row 마다 파일 하나를 `entity_type`, `entity_id`, `path`, `perm`, `is_default` 와 함께 저장한다. 엔티티마다 path 당 기본 row 는 최대 하나다. 사용자 API 와 세션이 이 row 를 사용한다.
- 파일 내용은 `auto_generated_file_revisions` 에 있고, 이 테이블은 row 만 추가한다. 생성은 revision 1 을 만들고 update 는 다음 `revision_number` 를 추가한다. 둘 다 소유자를 `creator_id` 로 한다. 가장 마지막 revision 이 현재 내용이다. update 는 `perm` 을 파일 row 에서 바로 수정한다.
- `(entity_type, entity_id)` 는 `ON DELETE CASCADE` 로 `virtual_entities` 를 참조한다. node 가 없는 엔티티에 생성하면 실패하고, script 소유자가 영구 삭제되는 동안 생성한 row 는 node 와 함께 삭제된다.
- 프로젝트와 도메인도 auto-generated file 을 own 하고, path 마다 default 로 지정된 파일이 하나다. domain-config 와 group-config 의 dotfile API 는 도메인이나 프로젝트를 owner 로 하여 `AutoGeneratedFileAdapter` 를 거쳐 같은 action 을 호출하므로, 그 스코프의 auto-generated file 권한이 gate 다. 기존 `dotfiles` column 은 읽지 않은 채 남고, 이후 migration 이 삭제한다.
- `create` 는 그 path 의 default 가 아닌 파일을 저장하고, `switch_default` 가 그 파일을 default 로 지정한다. 그 path 의 이전 default 파일은 default 가 아니게 된다. legacy dotfile 생성은 두 operation 을 서로 다른 트랜잭션에서 호출한다.
- adapter 의 v2 `purge` 는 파일을 먼저 읽고, path 의 default 파일이면 `DefaultDotfilePurgeForbidden` 으로 거절한다. 같은 path 의 다른 파일을 먼저 default 로 지정해야 한다. `purge` action 자체는 어떤 파일이든 삭제하고, legacy delete 는 이 action 으로 default 파일을 삭제한다.
- 요청은 파일마다 `data` 를 `MAXIMUM_DOTFILE_SIZE` 문자로 제한한다. revision row 의 CHECK 가 강제하는 한도다.
- adapter 가 `AutoGeneratedFileCreator` 를 생성한다. `CreateAutoGeneratedFileAction` 이 이를 `AutoGeneratedFileRepository` 에 전달하고, repository 가 한 트랜잭션에서 엔티티와 revision 1 을 생성한다.
- legacy 조회는 default 파일을 search 한 뒤 `GetCurrentAutoGeneratedFileRevisionsAction` 으로 가장 마지막 revision 을 읽는다. 이 action 은 파일마다 READ 를 확인한다. 세션 생성과 keypair hook payload 는 repository 안에서 가장 마지막 revision 을 읽는다.
- 마이그레이션은 keypair 의 byte 를 풀고, 사용자마다 `(path, perm, data)` 의 중복을 제거하며, 원본 중 기본 keypair 가 있었는지를 유지한다. row 를 batch 로 읽고 insert 마다 최대 1,000개 파일 row 를 쓴 뒤 `keypairs.dotfiles` 를 삭제한다.
- downgrade 는 사용자마다 기본 파일을 msgpack 으로 묶어 그 사용자의 모든 keypair 에 복원한다.
- auto-generated file 은 사용자 안에 생성하는 엔티티다. creator 가 그 node 를 생성하고, 사용자가 그 파일을 own 하고 govern 한다. `AutoGeneratedFileProcessors` 는 `auto_generated_file` 엔티티 타입으로 등록된다. 생성은 사용자 스코프에서 `auto_generated_file` create 권한을 확인하고, variant 를 포함해 이미 `MAXIMUM_DOTFILE_COUNT` 개 파일을 가진 소유자를 거부한다. search 는 사용자들의 스코프에서 읽고, update, switch-default, purge 는 파일 자체의 권한을 확인한다. legacy update 와 delete 는 path 로 기본 row 의 id 를 먼저 찾는다.
- 기존 dotfile API 에서는 access key 로 own 하는 사용자를 선택한다. 사용자, 프로젝트, 도메인을 영구 삭제하면 그 소유자의 스코프에서 파일을 node 와 함께 먼저 영구 삭제한다(`AutoGeneratedFileBatchPurger`). FK cascade 만으로는 row 만 삭제되고 node 는 남는다.

## service 에 남는 operation

생성, purge, bulk operation 묶음, 모든 keypair operation, 월별 통계, dotfile 쓰기 묶음은 service 에 남는다. 생성은 keypair 를 사용자와 함께 생성하고, purge 는 vfolder 와 세션, 배포 엔드포인트를 정리한다. global, 도메인별, 프로젝트별, 역할별 네 가지 조회는 ops 로 바로 간다.

## 역할은 사용자가 속한 스코프가 아니다

`search_users_by_role` 은 조건을 가진 global search 이지 scope search 가 아니다.
