# 허깅 페이스 레지스트리 adapter: 배경

규칙은 상위 디렉터리의 `AGENTS.md` 에 있다. 이 문서와 실행 결과가 어긋나면 문장을 먼저 의심한다.

허깅 페이스 레지스트리는 global 스코프에 생성된다. 허깅 페이스 레지스트리 하나는 연결 설정을 담는 row 와 이름을 담는 row, 두 row 이고 한 연산으로 함께 생성되고 함께 삭제된다. 허깅 페이스 레지스트리 하나를 수정하고 삭제하는 호출은 권한 그래프가 검사한다. 권한을 받은 사용자는 global 스코프에 부여된 역할로 아티팩트 레지스트리 권한을 받는다.

## 노드

adapter 가 반환하는 노드는 호출자가 superadmin 일 때만 저장된 `token` 을 담는다. 그 밖의 호출자는 monitor 와 수정 권한을 받은 사용자를 포함해 `token` 에 `*****` 를 받는다. token 이 없는 허깅 페이스 레지스트리는 모든 호출자에게 null 을 반환한다. 필드 타입은 그대로라 스키마는 바뀌지 않는다.

## 영구 삭제

단건 영구 삭제와 여럿 영구 삭제 모두 영구 삭제 권한을 검사한다.

## 여럿 수정

## 여럿 영구 삭제

여럿 연산은 호출 전체를 거부하지 않는다. 처리한 허깅 페이스 레지스트리는 처리된 목록에, 처리하지 못한 항목은 id 와 이유를 실패 목록에 담는다. 허깅 페이스 레지스트리마다 따로 생성하므로 하나가 실패해도 나머지는 반영된다. 여럿 영구 삭제의 처리된 목록에는 삭제한 허깅 페이스 레지스트리의 id 만 담긴다.

없는 id row 를 요청한 사용자가 superadmin 인 이유는, superadmin 이 검사를 모두 통과해 대상이 없음이 그대로 드러나기 때문이다. 권한을 받은 사용자에게 없는 id 는 권한 그래프에 없는 대상이다.
