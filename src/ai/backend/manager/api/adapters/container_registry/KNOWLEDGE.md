# 컨테이너 레지스트리 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다.

레지스트리에는 권한을 걸 수 없다. 어느 스코프에도 속하지 않게 만들어지고, 배선 열넷이 모두
전역이라 행을 지목하는 동작이 하나도 없다. 그래서 이 어댑터의 문은 전역 superadmin 역할
하나뿐이고, 권한 그래프가 지키는 문은 허용 프로젝트를 붙이고 떼는 자리에만 있다. 그 자리는
rbac의 관계 동작을 부르므로 거부하는 것도 다르다. 두 문을 짝을 따로 적는다.

## 만들기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필수 세 값만 주고 만든다 | 레지스트리 없음 | 주소·이름·종류로 만들기 | 나머지가 비어 있는 노드. 비밀번호는 답에 실리지 않는다 |
| 계정과 비밀번호를 함께 주고 만든다 | 레지스트리 없음 | 계정 정보까지 주고 만들기 | 계정 이름은 답에 있고 비밀번호 자리는 노드에 없다 |
| 허용 프로젝트를 함께 주고 만든다 | 프로젝트 하나가 있음 | 허용 목록을 붙여 만들기 | 레지스트리와 그 프로젝트의 연결이 함께 생긴다 |
| 주소 형식이 틀려도 만들어진다 | 레지스트리 없음 | `ftp://` 주소로 만들기 | 만들어진다 |
| 슈퍼관리자가 아닌 사용자가 만든다 | 권한 없음 | 만들기 | 역할로 거부 |
| 주소가 공백뿐이다 | 레지스트리 없음 | 빈 주소로 만들기 | 입력이 틀렸다는 이유로 거부 |
| 이름이 공백뿐이다 | 레지스트리 없음 | 빈 이름으로 만들기 | 입력이 틀렸다는 이유로 거부 |
| 없는 프로젝트를 허용 목록에 넣어 만든다 | 그 프로젝트가 없음 | 허용 목록을 붙여 만들기 | 프로젝트 없음으로 거부 |

주소 형식이 틀려도 만들어지는 줄이 따로 있는 이유는, 형식 검사가 수정 경로에만 있고 생성
경로에는 없기 때문이다. 공백 여부만 요청이 보고, `http`인지 `https`인지는 아무도 보지 않는다.
같은 값이 만들 때와 고칠 때 다르게 취급되므로 두 줄을 나란히 둔다.

원소마다 답하는 읽기처럼 보이지만 전역 조회를 부른다. 권한이 없으면 원소별로 갈리지 않고
요청 전체가 막히므로, 마지막 줄이 그것을 못박는다.

| 없는 레지스트리를 고친다 | 다른 레지스트리만 있음 | 주소 수정 | 대상 없음으로 거부 |
| 슈퍼관리자가 아닌 사용자가 고친다 | 같은 레지스트리가 있음 | 주소 수정 | 역할로 거부 |
| 주소를 http도 https도 아닌 값으로 바꾼다 | 그 레지스트리가 있음 | 주소 수정 | 주소 형식으로 거부 |
| harbor 종류인데 프로젝트를 비운다 | harbor 레지스트리가 있음 | 프로젝트 수정 | 프로젝트 값으로 거부 |

주소 형식과 프로젝트 값은 고친 뒤의 행을 보고 판단한다. 요청이 그 필드를 주지 않아도 저장된
값이 규칙을 어기면 거부되므로, 마지막 두 줄의 상황을 세울 때 요청과 저장된 값을 함께 세운다.

## 허용 프로젝트 붙이고 떼기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 프로젝트를 허용 목록에 넣는다 | 레지스트리와 프로젝트가 있고 둘 다 권한을 받음 | 넣기 | 연결이 생긴다 |
| 이미 허용된 프로젝트를 다시 넣는다 | 그 연결이 이미 있음 | 넣기 | 그대로 있고 중복이 생기지 않는다 |
| 허용된 프로젝트를 뺀다 | 그 연결이 있음 | 빼기 | 연결이 사라진다 |
| 없는 프로젝트를 넣는다 | 그 프로젝트가 없음 | 넣기 | 프로젝트 없음으로 거부 |
| 연결되지 않은 것만 뺀다 | 그 프로젝트가 연결돼 있지 않음 | 빼기 | 연결 없음으로 거부 |
| 지목한 스코프 중 한쪽만 허용된다 | 레지스트리에만 권한을 받음 | 넣기 | 권한 부족으로 거부 |

관계 동작은 엔티티 종류를 선언하지 않아 스코프에서 읽을 것이 없다. 지목한 스코프가 모두
허용해야 실행되고, 마지막 줄이 그 규칙을 본다. 거부하는 것이 역할이 아니라 권한 그래프라는
점에서 이 절은 다른 절과 다르다.

넣기의 중복은 SQL에서 건너뛰므로 오류가 아니고, 빼기는 지목한 것 중 하나도 지워지지 않았을
때만 거부한다. 둘의 비대칭을 두 줄로 나란히 둔다.

## 아직 적지 않은 것

어댑터가 내놓는 여섯 호출은 모두 위에 적혀 있다.

어댑터를 지나지 않는 배선 여덟은 이 문서의 대상이 아니다. 전체 조회 셋, 이미지 다시 훑기,
이미지 비우기, 프로젝트별 쿼터 넷은 REST v1 핸들러가 프로세서를 직접 부른다. 문이 없는 Harbor
웹훅도 그중 하나이며, 어댑터가 생기기 전에는 여기 적을 자리가 없다.
