# app_config 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 내용과 실행 결과가 어긋나면 문장 쪽을 먼저
의심한다.

app config는 자체 행이 없다. 조회할 때마다 세 테이블의 설정 조각을 병합해 만들어지는 값이고,
어느 행도 그 값에 대응하지 않는다. 세 테이블의 역할과 병합 규칙은
`../../../services/app_config/KNOWLEDGE.md`가 정하므로 여기서 되풀이하지 않는다.

이 어댑터의 호출은 조회 둘뿐이다. 하나는 세션의 사용자와 도메인으로 조회하고, 그 사용자 자신의
스코프에 부여된 읽기 권한을 검사한다. 다른 하나는 아무 스코프도 지정하지 않고 조회하며, 어떤
검사도 없다. 보호하는 것은 조회 방식 자체다 — 아무 스코프도 지정하지 않으므로 공개 조각만
병합된다.

행이 없으므로 다른 어댑터의 시나리오와 형태가 다르다. 성공 시나리오는 "생성한 뒤 조회한다"가
아니라 "세 테이블에 조각을 미리 만들어 두고 조회하면 병합 결과가 이렇게 나온다"이다. 응답은
이름과 병합된 설정 둘뿐이라 id도 시각도 없고, 설정은 통째로 비교한다. 생성·조회·삭제 시나리오도
없다. 조각이나 허용 목록 항목을 삭제한 뒤 병합이 어떻게 달라지는지는 그쪽 어댑터의 삭제 절이
다룬다.

## 자기 설정 조회

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 조각이 하나도 없는 이름을 조회한다 | 정의 하나, 허용 목록 항목도 조각도 없음, 자기 스코프에 읽기 권한 있음 | 그 이름 하나로 조회 | 그 이름 하나, 설정은 빈 값. 응답에서 빠지지 않는다 |
| 정의조차 없는 이름을 조회한다 | 정의 없음, 읽기 권한 있음 | 이름 하나로 조회 | 빈 설정. 정의가 없다고 거부되지 않는다 |
| 공개 조각만 있는 이름을 조회한다 | 정의 하나, 공개 허용 목록 항목 하나, 공개 조각 하나, 읽기 권한 있음 | 조회 | 설정이 공개 조각의 값과 같다 |
| 자기 조각이 도메인 조각을 덮어쓴다 | 도메인·사용자 허용 목록 항목이 기본 순위, 겹치는 키를 가진 도메인 조각과 자기 조각, 읽기 권한 있음 | 조회 | 겹치는 키는 자기 값, 겹치지 않는 키는 양쪽 모두 남는다 |
| 도메인 조각이 공개 조각을 덮어쓴다 | 공개·도메인 허용 목록 항목이 기본 순위, 겹치는 키를 가진 두 조각, 읽기 권한 있음 | 조회 | 겹치는 키는 도메인 값 |
| 관리자가 순위를 뒤집으면 도메인 조각이 자기 조각을 덮어쓴다 | 도메인 허용 목록 항목의 순위가 사용자 항목보다 큼, 겹치는 키를 가진 두 조각, 읽기 권한 있음 | 조회 | 겹치는 키는 도메인 값 |
| 중첩된 설정은 안쪽 키까지 병합된다 | 같은 키 아래 중첩 사전을 담은 두 조각, 읽기 권한 있음 | 조회 | 겹치지 않는 안쪽 키는 양쪽 모두 남고, 겹치는 안쪽 키만 뒤의 것이 남는다 |
| 목록은 통째로 바뀐다 | 같은 키에 목록을 담은 두 조각, 읽기 권한 있음 | 조회 | 뒤의 것의 목록만 남는다. 이어 붙지 않는다 |
| 명시적으로 비운 값도 덮어쓴다 | 앞 조각은 키에 값이 있고 뒤 조각은 같은 키가 비어 있음, 읽기 권한 있음 | 조회 | 그 키는 비어 있다 |
| 다른 사용자의 조각은 섞이지 않는다 | 도메인 하나, 사용자 둘, 사용자 허용 목록 항목 하나, 두 사용자 각자의 조각, 읽기 권한 있음 | 조회 | 자기 조각의 값만 |
| 다른 도메인의 조각은 섞이지 않는다 | 도메인 둘, 각 도메인의 조각, 도메인 허용 목록 항목 하나, 읽기 권한 있음 | 조회 | 자기 도메인 조각의 값만 |
| 여러 이름을 한 번에 조회하면 요청한 순서대로 반환된다 | 정의 셋, 각각의 허용 목록 항목과 조각, 읽기 권한 있음 | 이름 셋으로 조회 | 셋, 요청 순서대로, 각각 자기 병합 결과 |
| 같은 이름을 두 번 지정하면 두 번 반환된다 | 정의 하나, 조각 하나, 읽기 권한 있음 | 같은 이름 둘로 조회 | 둘, 같은 값 |
| 읽기 권한이 없는 사용자가 조회한다 | 정의 하나, 공개 조각 하나, 자기 스코프에 권한 없음 | 조회 | 권한 부족으로 거부 |
| 권한 검사를 끄면 권한 없이도 조회된다 | 권한 검사 비활성화, 권한 없음 | 조회 | 병합 결과가 반환된다 |

순위를 뒤집는 시나리오가 있는 이유는, 병합 순서를 허용 목록 항목이 결정하고 값의 소유자는 바꿀
수 없다는 것을 고정하기 위해서다. 순위는 허용 목록 항목에 있고 조각에는 없다.

목록과 빈 값의 시나리오가 따로 있는 이유는, 이 병합이 사전만 재귀적으로 파고들고 나머지는
통째로 바꾸기 때문이다. 목록을 이어 붙이거나 빈 값을 건너뛰는 병합과 다르다.

정의조차 없는 이름의 시나리오는 조각이 없는 이름과 같은 응답을 받는다. 이 조회는 정의를
확인하지 않고 조각만 본다.

허용 목록에 없는 스코프의 조각이 병합에 섞이는 시나리오는 두지 않는다. 그런 조각은 쓰이지 않고,
허용 목록 항목이 사라지면 조각도 함께 사라지므로 그 상황이 생기지 않는다. 그 두 시나리오는
설정 조각과 허용 목록 항목의 문서에 있다.

같은 이름의 두 허용 목록 항목이 같은 순위를 가지면 어느 조각이 이기는지 정해져 있지 않다.
시나리오를 적기 전에 정한다.

빈 이름 목록은 시나리오로 두지 않는다. 요청 타입이 이미 막으므로 어댑터가 보장하는 것이 아니다.

## 공개 설정 조회

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 로그인하지 않은 호출자가 공개 값을 조회한다 | 정의 하나, 공개·도메인·사용자 허용 목록 항목 셋, 조각 셋 | 이름 하나로 조회 | 설정이 공개 조각의 값과 같다. 도메인과 사용자 조각은 섞이지 않는다 |
| 공개 조각이 없는 이름을 조회한다 | 정의 하나, 사용자 조각만 있음 | 조회 | 빈 설정 |
| 정의조차 없는 이름을 조회한다 | 정의 없음 | 조회 | 빈 설정 |
| 로그인한 사용자가 조회해도 같은 응답을 받는다 | 첫 시나리오와 같은 조각 셋, 아무 권한도 없는 사용자 | 조회 | 공개 조각의 값만 |
| 여러 이름을 한 번에 조회하면 요청한 순서대로 반환된다 | 정의 셋, 각각의 공개 조각 | 이름 셋으로 조회 | 셋, 요청 순서대로 |

어떤 검사도 없다. 인증도 권한도 확인하지 않고, 권한 검사 스위치도 무관하다. 쓰기는 이 경로에
연결될 수 없게 막혀 있으므로 조회만 이 형태로 남는다.

공개 조각이 없는 이름과 정의조차 없는 이름이 같은 응답을 받는다. 그래서 이 조회로는 어떤 이름이
등록돼 있는지 알 수 없다. 그것이 검사 없는 경로가 아무것도 노출하지 않는다는 근거이므로 두
시나리오를 나란히 둔다.

로그인한 사용자의 시나리오는 이 조회가 호출자를 아예 보지 않는다는 것을 고정한다. 권한이 있어도
자기 조각이 섞이지 않고, 없어도 거부되지 않는다.

## 아직 적지 않은 것

어댑터가 제공하는 두 호출이 모두 위에 있다. 실행 결과에 남는 `batch_load_fields`는 어댑터 공통
기반 클래스가 물려주는 필드 읽기이고, 이 엔티티는 필드를 갖지 않아 호출할 일이 없다.
