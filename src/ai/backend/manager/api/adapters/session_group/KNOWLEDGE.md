# 세션 그룹 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 것과 실행 결과가 어긋나면 문장을 먼저
의심한다.

세션 그룹은 프로젝트와 소유자 아래에 생긴다. 그래서 개별 그룹을 읽는 문은 권한 그래프가
지키고, 전체 검색은 전역 superadmin 역할이 지킨다.

배포가 replica group을 만들 때 함께 생기는 그룹은 배포와 함께 관리된다. 사용자에게 내놓는
호출(하나 읽기, 여럿 읽기, 스코프 검색)은 이 그룹을 권한이 있어도 없는 것으로 답한다.
전체 검색만 이 그룹을 함께 보여준다.

공통 계약(대상 존재, 일괄 구성, 페이지)은 프레임워크 계약 테스트가 확인한다. 여기에는 연산마다
대표 성공과 대표 실패, 그리고 세션 그룹 규칙이 만드는 차이만 적는다.

## 하나 읽기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 권한을 받은 사용자가 사용자 그룹을 읽는다 | 프로젝트에 사용자가 만든 그룹 하나, 그 프로젝트에서 세션 그룹 읽기 권한을 받은 사용자 | id로 조회 | 그 그룹 |
| 아무 권한도 받지 않은 사용자가 읽는다 | 같은 그룹, 아무 권한도 받지 않은 사용자 | id로 조회 | 권한 부족으로 거부 |
| 권한을 받은 사용자가 배포의 그룹을 읽는다 | 배포의 replica group이 가진 그룹, 그 프로젝트에서 세션 그룹 읽기 권한을 받은 사용자 | id로 조회 | 대상 없음으로 거부 |

배포의 그룹 줄에서 사용자는 그 그룹에 대한 권한도 갖는다. 그래서 거부 이유가 권한이 아니라
대상 없음이어야 한다.

## 여럿 읽기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 권한을 받은 사용자가 사용자 그룹과 배포의 그룹을 함께 읽는다 | 같은 프로젝트에 사용자 그룹과 배포의 그룹, 그 프로젝트에서 세션 그룹 읽기 권한을 받은 사용자 | 두 id 목록으로 조회 | 요청한 순서대로 그 그룹, 빈 값 |
| 아무 권한도 받지 않은 사용자가 사용자 그룹을 읽는다 | 사용자 그룹 하나, 아무 권한도 받지 않은 사용자 | id 목록으로 조회 | 그 자리가 권한 부족으로 거부 |
| 슈퍼관리자가 아무 그룹도 갖지 않은 id를 읽는다 | 아무 권한도 받지 않은 슈퍼관리자 | 그 id 목록으로 조회 | 그 자리가 빈 값 |

여럿 읽기는 호출 전체를 거부하지 않고 자리마다 답한다. 배포의 그룹은 없는 그룹과 같은 빈 값으로
답한다.

없는 id의 줄은 슈퍼관리자가 부른다. 권한 검사는 id마다 권한 그래프를 보는데, 그래프에 없는 id는
권한을 확인할 수 없어 일반 사용자에게는 권한 부족으로 답한다. 검사를 통과하는 사람이어야 읽기의
답(빈 값)을 볼 수 있다.

## 전체 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 한 프로젝트의 그룹을 전체 검색으로 찾는다 | 같은 프로젝트에 사용자 그룹과 배포의 그룹, 아무 권한도 받지 않은 슈퍼관리자 | 그 프로젝트로 걸러 전체 검색 | 두 그룹 모두 |
| 슈퍼관리자가 아닌 사용자가 전체 검색한다 | 같은 그룹들, 그 프로젝트에서 세션 그룹 읽기 권한을 받은 사용자 | 전체 검색 | 역할로 거부 |

전체 검색의 문은 권한 그래프가 아니라 역할이다. 그래서 슈퍼관리자 줄의 행위자가 슈퍼관리자다.
다른 시나리오가 심은 그룹과 섞이지 않게 프로젝트로 거른다.

## 스코프 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 권한을 받은 사용자가 자기 프로젝트로 검색한다 | 그 프로젝트에 사용자 그룹과 배포의 그룹, 다른 프로젝트에 사용자 그룹, 그 프로젝트에서만 세션 그룹 읽기 권한을 받은 사용자 | 그 프로젝트 스코프로 검색 | 그 프로젝트의 사용자 그룹만 |
| 권한을 받지 않은 프로젝트로 검색한다 | 다른 프로젝트에서만 세션 그룹 읽기 권한을 받은 사용자 | 권한을 받지 않은 프로젝트 스코프로 검색 | 권한 부족으로 거부 |
| 그룹을 만든 사용자가 자기 스코프로 검색한다 | 두 프로젝트에 자기가 만든 그룹과 배포의 그룹, 다른 프로젝트에 다른 사용자가 만든 그룹, 자기 스코프에서 세션 그룹 읽기 권한을 받은 그 사용자 | 자기 사용자 스코프로 검색 | 두 프로젝트에 자기가 만든 그룹만 |
| 다른 사용자의 스코프로 검색한다 | 같은 그룹들, 그룹들이 있는 프로젝트에서만 세션 그룹 읽기 권한을 받은 사용자 | 그룹들을 만든 사용자의 스코프로 검색 | 권한 부족으로 거부 |
| 사용자 스코프와 프로젝트 스코프를 함께 넘긴다 | 같은 그룹들, 자기 스코프와 다른 프로젝트에서 세션 그룹 읽기 권한을 받은 그룹들을 만든 사용자 | 자기 사용자 스코프와 다른 프로젝트 스코프로 함께 검색 | 자기가 만든 그룹 둘과 그 프로젝트에서 다른 사용자가 만든 그룹 |

스코프 하나라도 권한이 없으면 나머지를 보여주지 않고 검색 전체를 거부한다.

스코프 여럿은 OR로 합친다. 마지막 줄에서 자기가 만든 첫 프로젝트의 그룹은 사용자 스코프로만,
다른 사용자의 그룹은 프로젝트 스코프로만 닿는다. 그래서 둘 다 나와야 합친 것이다.

## 아직 적지 않은 것

- 삭제 표시된 그룹이 기본 검색에서 빠지고, 삭제 시각으로 걸렀을 때만 나오는 것. 그룹에
  삭제 표시를 쓰는 연산이 아직 없어 그런 그룹을 심을 수 없다. 그룹 삭제 연산이 들어오면
  시나리오로 옮긴다.
