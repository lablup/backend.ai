# 세션 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다.

세션은 자기가 속한 프로젝트를 이름으로 댄다. 그래서 세션 권한은 프로젝트 스코프에 앉고, 그
역할을 주는 일이 곧 그 사람을 프로젝트 명부에 올리는 일이 된다.

## 조회

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 세션이 하나도 없을 때 슈퍼관리자가 훑는다 | 세션 없음 | 전체 조회 | 비어 있음 |
| 아무 권한도 받지 않은 사용자가 훑는다 | 권한 없음 | 전체 조회 | 역할 부족으로 거부 |
| 슈퍼관리자가 세션에 지정한 스케줄링 조건을 읽는다 | 세션 그룹, `designated_agent_ids`, `requested_starts_at`이 있는 세션 | 전체 조회 | 세 값이 저장된 그대로 반환되고 기존 세션 정보도 유지됨 |
| 슈퍼관리자가 스케줄링 조건을 지정하지 않은 세션을 읽는다 | 세션 그룹, `designated_agent_ids`, `requested_starts_at`이 없는 세션 | 전체 조회 | 세 값이 미설정으로 반환되고 기존 세션 정보도 유지됨 |

필터 없는 전체 조회는 슈퍼관리자 역할로 막힌다. 스코프 권한으로 막히는 조회는 스코프를
받는 검색이다.

## 여럿 종료하기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 대기 세션과 없는 id 하나를 한 번에 종료한다 | 대기 세션 하나 | 둘 종료 | 대기 세션은 취소됨, 없는 id 는 건너뜀으로 처리된 목록에 오고 실패한 것은 없음 |
| 프로젝트 범위에서 세션 soft delete 권한을 받은 사용자가 종료한다 | 그 프로젝트의 대기 세션 하나 | 종료 | 취소됨으로 처리된 목록에 옴 |
| 아무 권한도 받지 않은 사용자가 종료한다 | 같은 대기 세션 | 종료 | 종료된 것 없이 권한 부족 이유로 실패 목록에 옴 |
| 한 프로젝트 범위에서만 세션 soft delete 권한을 받은 사용자가 두 프로젝트의 세션을 한 번에 종료한다 | 두 프로젝트에 대기 세션 하나씩, 첫 프로젝트 범위에서 세션 soft delete 권한 | 둘 종료 | 첫 프로젝트의 세션은 취소됨으로 처리된 목록에, 다른 프로젝트의 세션은 권한 부족 이유로 실패 목록에 옴 |

여럿 종료는 호출 전체를 거부하지 않는다. 처리한 세션은 끝난 상태(취소됨, 종료 중, 강제 종료됨,
건너뜀)와 함께 처리된 목록에, 거부된 세션은 id 와 이유를 실패 목록에 싣는다. 이미 끝났거나 없는
세션은 건너뜀으로 처리된 목록에 온다.

## 종료하기 (옛 이름)

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 대기 세션을 종료한다 | 대기 세션 하나 | 종료 | 취소된 목록에 오고 나머지 목록은 비어 있음 |
| 아무 권한도 받지 않은 사용자가 종료한다 | 같은 대기 세션 | 종료 | 권한 부족으로 호출 전체가 거부됨 |

옛 종료는 여럿 종료와 같은 처리를 부르고 답을 끝난 상태별 목록으로 나눈다. 거부된 세션이
하나라도 있으면 호출 전체를 거부한다.

## 여러 세션의 할당을 한 번에 읽기

다른 엔티티가 가리키는 세션들의 할당을 id 목록으로 한 번에 읽는다. 답은 id마다 한 자리씩 입력
순서대로 오고, 호출 전체가 거부되지는 않는다. 자리마다 세션 조회 권한으로 따로 판정한다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 프로젝트 범위에서 세션 조회 권한을 받은 사용자가 그 프로젝트의 세션 할당을 읽는다 | 두 프로젝트에 대기 세션 하나씩, 첫 프로젝트 범위에서 세션 조회 권한 | 첫 프로젝트의 세션 하나 | 빈 할당 |
| 한 프로젝트 범위에서만 세션 조회 권한을 받은 사용자가 두 프로젝트의 세션 할당을 읽는다 | 두 프로젝트에 대기 세션 하나씩, 첫 프로젝트 범위에서 세션 조회 권한 | 첫 프로젝트의 세션, 다른 프로젝트의 세션 순 | 순서대로 빈 할당, 권한 부족 거부 |
| 아무 권한도 받지 않은 사용자가 두 프로젝트의 세션 할당을 읽는다 | 같은 두 세션, 권한 없음 | 같은 순서 | 두 자리 모두 권한 부족 거부 |

할당 행이 없는 세션은 요구량, 사용량, 할당량이 모두 빈 할당으로 온다.

## 아직 적지 않은 것

`designated_agent_ids`가 빈 목록으로 저장된 세션은 빈 목록 그대로 반환해야 한다. 현재 세션 생성
spec은 빈 목록을 미설정(`None`)으로 저장하므로, 빈 목록이 저장된 기존 행의 조회는 시나리오로 심을 수 없다.

조회 시나리오는 세션 생성 spec으로 저장한 세션을 읽는다. `enqueue`를 거치는 생성 요청과
스케줄러의 리소스 검증은 아직 시나리오로 옮기지 않았다.

`admin_search_kernels`, `batch_load_by_ids`,
`batch_load_kernels_by_ids`, `batch_resource_allocation_by_kernel`,
`compute_schedule`, `enqueue`,
`exclude_idle_checks`, `get`, `get_logs`, `gql_search_by_project`,
`include_idle_checks`, `project_search`, `scoped_search`, `search_kernels_by_agent`,
`search_kernels_by_session`, `search_sessions_by_agent`, `shutdown_service`,
`start_service`, `update`.
