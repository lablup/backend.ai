# 폴더 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다.

개인 폴더는 만든 사람의 스코프에 생긴다. 그래서 폴더를 만들 권한은 그 사용자 자신에게
걸린다. 폴더가 놓일 스토리지 호스트는 도메인과 키페어 정책이 함께 허용해야 한다.

| 아무 권한도 받지 않은 사용자가 만든다 | 권한 없음 | 만들기 | 권한 부족으로 거부 |

## 누구의 폴더에 닿는가

폴더는 프로젝트 아래에 있다. 개인 폴더는 그 사람의 개인 프로젝트에, 프로젝트 폴더는 그
프로젝트에 있다. 공유는 다른 스코프가 폴더를 제한을 두고 빌려 받는 것이다. 폴더에 닿는지는
폴더를 가진 스코프에 역할이 폴더 읽기를 허용하는지로 정해진다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 자기 폴더를 읽는다 | 자기 개인 폴더 하나, 자기 개인 프로젝트에 폴더 읽기 권한 | 한 폴더 읽기 | 그 폴더 |
| 권한 없이 자기 폴더를 읽는다 | 자기 개인 폴더 하나, 권한 없음 | 한 폴더 읽기 | 권한 부족으로 거부 |
| 프로젝트 역할로 프로젝트 폴더를 훑는다 | 프로젝트에 폴더 하나, 그 프로젝트에 폴더 읽기 권한 | 프로젝트 폴더 조회 | 그 폴더 |
| 권한 없이 프로젝트 폴더를 훑는다 | 프로젝트에 폴더 하나, 권한 없음 | 프로젝트 폴더 조회 | 권한 부족으로 거부 |
| 받아들인 공유로 남의 폴더를 읽는다 | 남의 개인 폴더가 읽기로 공유 제안되어 받아들임, 자기 개인 프로젝트에 폴더 읽기 권한 | 한 폴더 읽기 | 그 폴더 |
| 받아들이지 않은 공유로 남의 폴더를 읽는다 | 남의 개인 폴더가 읽기로 공유 제안만 됨, 자기 개인 프로젝트에 폴더 읽기 권한 | 한 폴더 읽기 | 권한 부족으로 거부 |

## 여러 폴더를 한 번에 읽기

다른 엔티티가 가리키는 폴더들을 id 목록으로 한 번에 읽는다. 답은 id마다 한 자리씩 입력 순서대로
오고, 호출 전체가 거부되지는 않는다. 자리마다 한 폴더 읽기와 같은 기준으로 따로 판정한다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 자기 폴더를 id로 읽는다 | 자기 개인 폴더 하나, 자기 개인 프로젝트에 폴더 읽기 권한 | 그 폴더 id 하나 | 그 폴더 |
| 권한 없이 자기 폴더를 id로 읽는다 | 자기 개인 폴더 하나, 권한 없음 | 그 폴더 id 하나 | 그 자리는 권한 부족 거부 |
| 읽을 수 있는 폴더, 읽을 수 없는 폴더, 없는 id를 함께 읽는다 | 자기 개인 폴더 하나, 남의 개인 폴더 하나, 자기 개인 프로젝트에 폴더 읽기 권한 | 자기 폴더, 남의 폴더, 없는 id 순 | 순서대로 그 폴더, 권한 부족 거부, 권한 부족 거부 |
| 받아들인 공유로 남의 폴더를 id로 읽는다 | 남의 개인 폴더가 읽기로 공유 제안되어 받아들임, 자기 개인 프로젝트에 폴더 읽기 권한 | 그 폴더 id 하나 | 그 폴더 |
| 받아들이지 않은 공유로 남의 폴더를 id로 읽는다 | 남의 개인 폴더가 읽기로 공유 제안만 됨, 자기 개인 프로젝트에 폴더 읽기 권한 | 그 폴더 id 하나 | 그 자리는 권한 부족 거부 |
| 슈퍼관리자가 있는 폴더와 없는 id를 함께 읽는다 | 남의 개인 폴더 하나, 행위자는 슈퍼관리자 | 그 폴더 id와 없는 id | 그 폴더, 없는 id 자리는 빈 값 |
| 빈 목록으로 읽는다 | 권한 없음 | 빈 id 목록 | 빈 목록 |

슈퍼관리자가 아닌 사용자에게는 없는 id도 권한 부족으로 거부된다. 폴더가 없다는 사실은 권한 없는
사용자에게 드러나지 않는다. 빈 값은 슈퍼관리자만 본다.

## 여러 폴더의 권한과 마운트 수준을 한 번에 읽기

다른 엔티티가 가리키는 폴더들에서 호출자가 가진 권한과 마운트 수준을 id 목록으로 한 번에 읽는다.
id마다 따로 판정해 입력 순서대로 답하는 일괄 구성은 프레임워크 계약 테스트가 확인한다. 여기에는
id 하나로 대표 성공과 대표 실패만 적는다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 자기 폴더의 권한을 읽는다 | 자기 개인 폴더 하나, 자기 개인 프로젝트에 폴더 읽기 권한 | 그 폴더 id 하나 | 읽기 권한 |
| 권한 없이 자기 폴더의 권한을 읽는다 | 자기 개인 폴더 하나, 권한 없음 | 그 폴더 id 하나 | 그 자리는 권한 부족 거부 |
| 자기 폴더의 마운트 수준을 읽는다 | 자기 개인 폴더 하나, 자기 개인 프로젝트에 폴더 읽기 권한 | 그 폴더 id 하나 | 읽기 쓰기 |
| 권한 없이 자기 폴더의 마운트 수준을 읽는다 | 자기 개인 폴더 하나, 권한 없음 | 그 폴더 id 하나 | 그 자리는 권한 부족 거부 |

자기 개인 폴더는 폴더의 기본 마운트 권한과 상관없이 읽기 쓰기로 마운트된다.

## 수정

수정은 이름, 복제 가능 여부, 기본 마운트 권한을 바꾼다. 이름은 폴더를 가진 스코프 안에서 겹치지
않아야 한다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 권한을 받은 사용자가 자기 폴더를 수정한다 | 자기 개인 폴더 둘, 자기 개인 프로젝트에 폴더 수정 권한 | 첫 폴더의 이름과 복제 가능 여부 수정 | 바뀐 폴더 |
| 이미 쓰는 이름으로 바꾼다 | 자기 개인 폴더 둘, 자기 개인 프로젝트에 폴더 수정 권한 | 첫 폴더를 둘째 폴더의 이름으로 수정 | 잘못된 값으로 거부 |
| 아무 권한도 받지 않은 사용자가 수정한다 | 자기 개인 폴더 둘, 권한 없음 | 첫 폴더 수정 | 권한 부족으로 거부 |

## 여럿 수정, soft delete, restore

여럿 연산은 호출 전체를 거부하지 않는다. 폴더마다 한 폴더 연산과 같은 기준으로 따로 판정해,
처리한 폴더는 처리된 목록에, 처리하지 못한 것은 id 와 이유를 실패 목록에 싣는다. soft delete 와
restore 는 같은 권한을 본다. 여럿 purge 는 이 형태가 아니다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 수정 권한을 받은 사용자가 여럿을 수정한다 | 자기 개인 폴더 둘, 남의 개인 폴더 하나, 자기 개인 프로젝트에 폴더 수정 권한 | 셋을 복제 가능으로 수정 | 자기 폴더 둘은 수정되어 오고, 남의 폴더는 권한 부족 이유로 실패 목록에 옴 |
| 아무 권한도 받지 않은 사용자가 여럿을 수정한다 | 같은 폴더 셋, 권한 없음 | 셋 수정 | 수정된 것 없이 셋 다 권한 부족 이유로 실패 목록에 옴 |
| soft delete 권한을 받은 사용자가 여럿을 soft delete 한다 | 같은 폴더 셋, 자기 개인 프로젝트에 폴더 soft delete 권한 | 셋 soft delete | 자기 폴더 둘은 삭제 대기로 오고, 남의 폴더는 권한 부족 이유로 실패 목록에 옴 |
| 아무 권한도 받지 않은 사용자가 여럿을 soft delete 한다 | 같은 폴더 셋, 권한 없음 | 셋 soft delete | soft delete 된 것 없이 셋 다 권한 부족 이유로 실패 목록에 옴 |
| soft delete 된 여럿을 한 번에 restore 한다 | 같은 폴더 셋, 자기 개인 프로젝트에 폴더 soft delete 권한 | 자기 폴더 둘 soft delete 뒤 둘 restore | 둘 다 쓸 수 있는 상태로 옴 |
