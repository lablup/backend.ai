# entity_label adapter: 배경

규칙은 상위 디렉터리의 `AGENTS.md` 에 있다. 이 문서와 실행 결과가 어긋나면 문장을 먼저 의심한다.

레이블은 어느 엔티티에나 붙는 `key=value` 한 쌍이다. 레이블 자체는 권한을 갖지 않고, 모든 호출은 레이블이 붙는 엔티티의 권한으로 응답한다. 쓰기는 그 엔티티의 수정 권한, 읽기는 조회 권한이다. superadmin 은 모든 검사를 통과한다.

호출은 여섯이다. 하나 설정, 여럿 설정, 하나 삭제, 여럿 삭제, 지정한 엔티티들의 레이블 검색, 이미 가진 엔티티 하나의 레이블 검색이다. 단건 쓰기는 전체가 성공하거나 전체가 거부되고, 일괄 쓰기는 엔티티마다 또는 레이블마다 따로 응답한다.

여럿 설정과 여럿 삭제는 이름이 복수인 GQL mutation 과 `partial-bulk-` 로 시작하는 REST 경로로 호출한다. 단수 이름의 mutation 과 `bulk-` 경로는 deprecated 이고 같은 호출로 이어진다.

엔티티 타입은 연결 및 호출 경로가 처리하는 것만 지정할 수 있다. 처리되지 않는 타입을 담은 요청은 어느 호출이든 잘못된 요청으로 전체가 거부된다. 일괄 쓰기도 예외가 아니다. 그것은 엔티티 하나의 결과가 아니라 요청 자체의 잘못이기 때문이다.

## 하나 설정

엔티티가 실제로 있는지는 확인하지 않는다. 레이블 row 는 엔티티 row 를 외래 키로 참조하지 않으므로, 권한 검사를 통과한 호출은 없는 id 에도 레이블을 생성한다. superadmin 이 없는 id 에 레이블을 붙이는 호출이 그래서 성공한다. superadmin 이 아닌 사용자는 없는 엔티티에 권한을 받을 수 없으므로 권한 부족으로 거부된다.

키나 값이 비어 있거나 길이 제한을 넘는 요청은 시나리오로 두지 않는다. 요청 타입이 이미 거부하므로 adapter 가 보장하는 동작이 아니다.

## 여럿 설정

한 요청에 엔티티 여럿과 키 여럿을 담는다. 응답은 엔티티마다 하나다. 한 엔티티에 붙일 키들은 함께 생성되거나 함께 거부된다. 실패 목록은 요청 항목 단위다. 거부된 엔티티에 붙이려던 키마다 엔티티, 키, 이유를 담은 항목이 하나씩 온다. 호출 자체는 거부되지 않는다.

실패 목록의 이유는 문자열이고 문자열은 바뀔 수 있는 값이다. 시나리오는 이유가 있다는 것만 확인한다.

## 하나 삭제

레이블은 자기 id 로 지정된다. 어느 엔티티가 응답하는지는 row 를 먼저 읽어 알아내고, 그 읽기는 엔티티의 조회 권한을 요구한다. 없는 id 와 조회 권한이 없는 엔티티의 레이블은 같은 이유로 거부된다. id 가 있는지를 응답으로 알 수 없게 하기 위해서다. superadmin 은 이 병합을 거치지 않으므로 없는 id 는 대상 없음으로 거부된다.

## 여럿 삭제

레이블 id 여럿을 한 번에 지정한다. 응답은 레이블마다 하나다. 엔티티들을 한 번에 읽고 엔티티마다 수정 권한을 요구한다. 거부된 엔티티의 레이블과 없는 id 는 이유를 담아 실패 목록에 오고, 나머지는 실패 항목과 분리되어 성공 목록에 온다. 호출 자체는 거부되지 않는다.

지정한 id 가 모두 없을 때 하위 계층은 응답할 엔티티가 없어 전체를 거부한다. adapter 가 그것을 id 마다 실패 항목으로 되돌려 놓으므로, 호출자는 무엇을 지정했든 한 가지 모양으로 읽는다. "모든 id 가 없다" 시나리오가 그것을 증명한다.

## 검색

지정한 엔티티들의 레이블을 한 페이지로 읽는다. 엔티티마다 조회 권한을 요구하고, 하나라도 거부되면 읽기 전체가 거부된다. 읽기는 전체가 성공하거나 전체가 실패한다.

이미 가진 엔티티 하나의 레이블을 읽는 호출은 엔티티 하나로 호출하는 같은 읽기다. 엔티티를 다시 지정하지 않고 노드가 스스로를 지정한다는 점만 다르다. 시나리오는 검색 절의 엔티티 하나짜리 row 와 같으므로 따로 두지 않는다.
