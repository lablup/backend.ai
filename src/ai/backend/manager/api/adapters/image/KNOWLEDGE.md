# 이미지 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다.

이미지의 문은 둘이다. 훑기와 별칭과 수정은 전역 superadmin 역할이 지키고, 물리기·되살리기·
지우기 셋만 권한 그래프가 지킨다. 그 셋에는 문이 하나 더 있다. 게이트를 지난 뒤 서비스가
소유권을 다시 보고, 커스터마이즈되지 않은 이미지는 주인이 없어 언제나 거부된다. 게이트로
거부되는 것과 소유권으로 거부되는 것이 서로 다르므로 짝을 따로 적는다.

## 훑기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필터 없이 훑는다 | 이미지 둘을 심음 | 전체 조회 | 둘을 모두 셈 |
| 페이지 크기를 생략한다 | 이미지 쉰하나를 심음 | 크기 없이 조회 | 쉰 건까지 오고 다음 쪽이 있다고 답한다 |
| 슈퍼관리자가 아닌 사용자가 훑는다 | 권한 없음 | 전체 조회 | 역할로 거부 |
| 커서로 앞에서부터 훑는다 | 이미지 셋을 심음 | 커서 조회 | 앞의 둘과 다음 쪽 표시 |
| 바깥에서 준 조건이 먼저 걸린다 | 레지스트리가 다른 이미지 둘 | 한 레지스트리로 좁힌 조회 | 그 레지스트리의 것만 남음 |

앞의 셋은 오프셋만 받는 훑기, 뒤의 넷은 커서도 받는 훑기다. 바깥에서 준 조건은 커서 쪽에만
있고 사용자가 준 필터보다 먼저 걸리므로, 다섯째 줄이 그 순서를 본다.

여덟째 줄이 이 어댑터에서 가장 중요한 줄이다. 게이트를 통과한 사용자가 그다음 소유권 검사에서
막히므로, 권한 부족과 접근 금지는 서로 다른 것이어야 한다. 하나로 뭉치면 권한을 더 주면
되는지 아닌지를 호출자가 알 수 없다.

같은 이미지에 대해 두 문이 서로 다르게 거부한다.

가속기 목록만 세 갈래(생략·비우기·값 주기)를 받는다. 나머지 항목은 생략과 값 주기 둘뿐이므로
셋째 줄은 가속기에만 둔다.

## 답이 행위자에 따라 달라진다

에이전트 설치 정보를 가리는 설정이 켜져 있으면, 슈퍼관리자가 아닌 호출자에게는 그 정보가 빈
채로 온다. 같은 이미지를 같은 요청으로 읽어도 답이 갈리므로 훑기의 성공 줄을 행위자마다 따로
세운다. 이 갈림은 이 어댑터에만 있다.

## 아직 적지 않은 것

어댑터가 내놓는 열한 호출은 모두 위에 적혀 있다.

어댑터를 지나지 않는 배선 열넷은 이 문서의 대상이 아니다. 레지스트리 훑기, 에이전트에 미리
싣기와 내리기, 에이전트에서 지우기, 레지스트리에서 태그 떼기, 자원 한도 설정과 해제, 그리고
이름으로 지목하는 옛 경로들은 REST v1 핸들러가 프로세서를 직접 부른다.
