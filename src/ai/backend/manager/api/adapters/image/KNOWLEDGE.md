# 이미지 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 내용과 실행 결과가 다르면 문장을 먼저
의심한다.

호출을 막는 검사가 세 가지다.

| 검사 | 적용되는 호출 | 확인하는 것 |
|---|---|---|
| 슈퍼관리자 검사 | 검색, 별칭, 수정 | 호출자가 슈퍼관리자인가 |
| 이미지 권한 검사 | 소프트 삭제, 복원, 완전 삭제, 여러 ID 조회(원소마다) | 호출자가 해당 이미지의 권한을 받았는가 |
| 커스텀 이미지 작성자 검사 | 소프트 삭제, 복원, 완전 삭제 | 이미지가 커스텀 이미지이고 호출자가 만들었는가 |

뒤의 두 검사는 차례로 실행된다. 이미지 권한 검사를 통과해도 커스텀 이미지 작성자
검사가 남는다.

이미지는 컨테이너 레지스트리에 속한다. 레지스트리 자체의 호출은
`../container_registry/KNOWLEDGE.md`에 있다.

## 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필터 없이 검색한다 | 이미지 2개, 호출자는 슈퍼관리자 | 전체 조회 | 이미지 2개가 반환되고 전체 개수는 2 |
| 이름으로 필터링한다 | 이미지 3개, 호출자는 슈퍼관리자 | 한 이미지의 이름으로 조회 | 해당 이미지 1개만 반환 |
| 상태로 필터링한다 | 살아 있는 이미지와 삭제된 이미지, 호출자는 슈퍼관리자 | 살아 있는 이미지 조회 | 살아 있는 이미지만 반환 |
| 정렬과 오프셋을 함께 지정한다 | 이미지 4개, 호출자는 슈퍼관리자 | 이름 내림차순, 첫 항목 제외, 2개 조회 | 정렬된 결과의 두 번째와 세 번째 항목, 앞뒤 페이지 표시 |
| 페이지 크기를 생략한다 | 이미지 51개, 호출자는 슈퍼관리자 | 크기 없이 조회 | 50개가 반환되고 다음 페이지가 있음 |
| 커서만 지정한다 | 이미지 3개, 호출자는 슈퍼관리자 | 크기와 오프셋 없이 커서로 2개 조회 | 앞의 2개와 다음 페이지 표시 |
| 크기와 커서를 함께 지정한다 | 이미지 3개, 호출자는 슈퍼관리자 | 크기 1과 커서를 함께 지정한 조회 | 커서는 무시되고 크기대로 1개 |
| 슈퍼관리자가 아닌 사용자가 검색한다 | 이미지 2개, 호출자는 일반 사용자 | 전체 조회 | 슈퍼관리자 권한 부족으로 거부 |

요청 타입은 크기·오프셋과 커서를 모두 받는다. 커서만 지정하면 커서로 읽고, 크기나 오프셋이
하나라도 있으면 오프셋으로 읽는다. 커서만 지정한 요청을 첫 페이지로 답하는 것은 결함이다.

커서를 사용하는 검색은 따로 있다. 이미지와 별칭에 하나씩이다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 커서로 앞에서부터 읽는다 | 이미지 3개, 호출자는 슈퍼관리자 | 커서 조회 | 앞의 2개와 다음 페이지 표시 |
| 호출 측이 지정한 조건이 먼저 적용된다 | 레지스트리가 서로 다른 이미지 2개씩, 호출자는 슈퍼관리자 | 한 레지스트리로 좁힌 조회 | 해당 레지스트리의 이미지만 반환 |
| 페이지 방식을 두 가지 함께 지정한다 | 이미지 2개, 호출자는 슈퍼관리자 | 크기와 커서를 함께 지정한 조회 | 입력이 잘못되어 거부 |
| 커서 값이 잘못되어 있다 | 이미지 2개, 호출자는 슈퍼관리자 | 잘못된 커서로 조회 | 커서가 잘못되어 거부 |
| 별칭이 하나도 없다 | 별칭 없음, 호출자는 슈퍼관리자 | 별칭 조회 | 빈 목록 |
| 등록된 별칭을 검색한다 | 별칭 1개, 호출자는 슈퍼관리자 | 별칭 조회 | 해당 별칭이 반환 |
| 이미지별로 별칭을 필터링하고 정렬한다 | 이미지 2개에 별칭 3개, 호출자는 슈퍼관리자 | 한 이미지의 별칭을 이름 내림차순으로 조회 | 해당 이미지의 별칭만 내림차순으로 반환 |
| 슈퍼관리자가 아닌 사용자가 별칭을 검색한다 | 이미지 2개, 호출자는 일반 사용자 | 별칭 조회 | 슈퍼관리자 권한 부족으로 거부 |

페이지 방식을 두 가지 함께 지정하거나 커서 값이 잘못된 경우의 거부는 요청 타입이 막는 것이
아니다. 어댑터가 페이지 방식을 고르는 과정에서 발생한다. 어댑터가 보장하는 동작이므로
시나리오로 남긴다.

호출 측이 지정하는 기본 조건은 커서를 사용하는 검색에만 있다. 요청의 필터보다 먼저
적용되므로 "호출 측이 지정한 조건이 먼저 적용된다"가 그 순서를 확인한다.

| 아무 권한도 받지 않은 사용자가 별칭 ID로 조회한다 | 별칭 1개, 아무 권한도 없음 | 별칭 ID 2개를 한 번에 조회 | 있는 별칭 자리는 권한 부족 거부, 없는 ID 자리는 비어 있음 |

여러 ID 조회는 요청 전체가 아니라 원소마다 이미지 권한 검사를 거친다. 거부된 원소는 예외
객체로 그 자리에 담기고, 나머지 원소는 그대로 온다.

## 소프트 삭제와 복원

소프트 삭제는 행을 지우지 않는다. 상태만 삭제됨으로 바꾸므로 복원할 수 있다. 행까지 없애는
것은 아래의 완전 삭제다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이미지를 소프트 삭제한다 | 살아 있는 이미지, 호출자는 슈퍼관리자 | 소프트 삭제 | 삭제됨 상태가 담긴 노드, 행은 남음 |
| 커스텀 이미지 작성자가 자기 이미지를 소프트 삭제한다 | 자기가 만든 커스텀 이미지, 해당 이미지의 삭제 권한 있음 | 소프트 삭제 | 삭제됨 상태가 담긴 노드 |
| 소프트 삭제한 것을 복원한다 | 삭제된 이미지, 호출자는 슈퍼관리자 | 복원 | 살아 있는 상태가 담긴 노드 |
| 삭제하지 않은 것을 복원한다 | 살아 있는 이미지, 호출자는 슈퍼관리자 | 복원 | 살아 있는 상태 그대로 |
| 존재하지 않는 ID를 소프트 삭제한다 | 다른 이미지만 있음, 호출자는 슈퍼관리자 | 소프트 삭제 | 대상을 찾을 수 없어 거부 |
| 존재하지 않는 ID를 복원한다 | 다른 이미지만 있음, 호출자는 슈퍼관리자 | 복원 | 대상을 찾을 수 없어 거부 |
| 아무 권한도 받지 않은 사용자가 소프트 삭제한다 | 커스터마이즈되지 않은 이미지, 아무 권한도 없음 | 소프트 삭제 | 권한 부족으로 거부 |
| 아무 권한도 받지 않은 사용자가 복원한다 | 커스터마이즈되지 않은 이미지, 아무 권한도 없음 | 복원 | 권한 부족으로 거부 |
| 일반 이미지는 권한을 받은 사용자도 삭제하지 못한다 | 커스텀 이미지가 아님, 호출자에게 이미지 삭제 권한 있음 | 소프트 삭제 | 커스텀 이미지 작성자 검사에서 거부 |
| RBAC 권한 검사를 꺼도 작성자 검사는 남는다 | RBAC 권한 검사 비활성화, 커스텀 이미지가 아님 | 소프트 삭제 | 커스텀 이미지 작성자 검사에서 거부 |
| 완전 삭제 중인 이미지를 소프트 삭제한다 | 완전 삭제 중인 이미지, 호출자는 슈퍼관리자 | 소프트 삭제 | 대상을 찾을 수 없어 거부 |

"일반 이미지는 권한을 받은 사용자도 삭제하지 못한다"는 이미지 권한 검사와 커스텀 이미지 작성자
검사가 별개임을 확인한다.

그래서 권한 부족과 접근 금지를 하나로 합치면 안 된다. 합치면 권한을 더 받으면 되는 상황인지를
호출자가 구분할 수 없다.

커스텀 이미지가 아니면 작성자 검사를 통과할 수 없다. 슈퍼관리자만 이 검사를 건너뛰고
삭제할 수 있다. 이는 이미지와 레지스트리의 RBAC 소유 관계를 의미하지 않는다.

복원은 삭제된 이미지와 살아 있는 이미지를 대상으로 삼는다. 살아 있는 것을 복원하면 아무것도
바꾸지 않는다.

## 별칭 등록과 해제

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 별칭을 등록한다 | 이미지 1개, 호출자는 슈퍼관리자 | 별칭 등록 | 별칭 ID와 이름, 해당 이미지의 ID |
| 등록한 별칭을 해제한다 | 별칭이 등록되어 있음, 호출자는 슈퍼관리자 | 별칭 해제 | 해제된 별칭과 해당 이미지의 ID |
| 존재하지 않는 ID에 별칭을 등록한다 | 다른 이미지만 있음, 호출자는 슈퍼관리자 | 별칭 등록 | 대상을 찾을 수 없어 거부 |
| 이미 사용 중인 별칭을 등록한다 | 해당 별칭이 등록되어 있음, 호출자는 슈퍼관리자 | 별칭 등록 | 유니크 제약 위반으로 거부 |
| 존재하지 않는 별칭을 해제한다 | 다른 별칭만 있음, 호출자는 슈퍼관리자 | 별칭 해제 | 대상을 찾을 수 없어 거부 |
| 커스텀 이미지 작성자가 자기 이미지에 별칭을 등록한다 | 자기가 만든 커스텀 이미지, 해당 이미지의 권한 있음 | 별칭 등록 | 슈퍼관리자 권한 부족으로 거부 |
| 슈퍼관리자가 아닌 사용자가 별칭을 해제한다 | 별칭이 등록되어 있음, 호출자는 일반 사용자 | 별칭 해제 | 슈퍼관리자 권한 부족으로 거부 |

별칭은 이미지에 딸린 값이다. 등록과 해제는 이미지 권한이 아니라 슈퍼관리자 검사로 보호된다.
소프트 삭제를 막는 검사와 달라서, 같은 이미지에 대해 두 검사가 서로 다르게 거부한다. "커스텀
이미지 작성자가 자기 이미지에 별칭을 등록한다"가 그 차이를 확인한다. 커스텀 이미지 작성자라도
자기 이미지에 별칭을 등록할 수는 없다.

| 가속기 이름을 지정한다 | 가속기가 지정되지 않은 이미지, 호출자는 슈퍼관리자 | 가속기 이름을 주는 수정 | 해당 이름이 담긴 노드 |
| 나머지 기본 필드를 함께 수정한다 | 이미지 1개, 호출자는 슈퍼관리자 | 이름, 레지스트리, 이미지 경로, 아키텍처, 크기, 유형, 다이제스트, 로컬 여부 수정 | 지정한 값이 담긴 노드 |
| 레이블과 리소스 제한을 함께 수정한다 | 이미지 1개, 호출자는 슈퍼관리자 | 레이블과 CPU 하한·상한 수정 | 지정한 레이블과 리소스 제한이 담긴 노드 |
| 존재하지 않는 ID를 수정한다 | 다른 이미지만 있음, 호출자는 슈퍼관리자 | 태그 수정 | 대상을 찾을 수 없어 거부 |
| 슈퍼관리자가 아닌 사용자가 수정한다 | 이미지 1개, 호출자는 일반 사용자 | 태그 수정 | 슈퍼관리자 권한 부족으로 거부 |

가속기 목록만 세 가지 요청을 구분한다. 생략, 비우기, 값 지정이다. 나머지 필드는 생략과 값
지정 두 가지뿐이라 세 번째 경우는 가속기에만 둔다.
