# 이미지 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 것과 실행 결과가 어긋나면 문장을 먼저
의심한다.

문이 셋이다.

| 문 | 어느 호출에 | 무엇을 보는가 |
|---|---|---|
| 전역 역할 | 검색, 별칭, 고치기 | 슈퍼관리자인가 |
| 엔티티 권한 | 잊기, 되살리기, 지우기 | 그 이미지에 권한을 받았는가 |
| 소유권 | 잊기, 되살리기, 지우기 | 커스터마이즈된 이미지이고 부르는 사람이 만들었는가 |

뒤의 둘은 이어서 돈다. 게이트를 지나도 소유권 검사가 남는다. 집행 스위치는 게이트까지만 닿고
소유권 검사에는 닿지 않는다.

이미지는 컨테이너 레지스트리 아래에 만들어진다. 레지스트리 자체의 호출은
`../container_registry/KNOWLEDGE.md`에 있다.

## 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필터 없이 검색한다 | 이미지 둘, 전역 역할 있음 | 전체 조회 | 둘을 모두 센다 |
| 페이지 크기를 생략한다 | 이미지 쉰하나, 전역 역할 있음 | 크기 없이 조회 | 쉰 건까지 오고 다음 쪽이 있다고 답한다 |
| 슈퍼관리자가 아닌 사용자가 검색한다 | 전역 역할 없음 | 전체 조회 | 역할로 거부 |

요청 타입은 커서를 받지만 이 검색은 읽지 않는다. 크기와 건너뛸 수만 본다. 커서를 함께 주면
지금은 조용히 버려진다. 버릴 것인지 쓸 것인지 정하고 줄을 적는다.

커서를 읽는 검색은 따로 있다. 이미지와 별칭 각각에 하나씩이다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 커서로 앞에서부터 읽는다 | 이미지 셋, 전역 역할 있음 | 커서 조회 | 앞의 둘과 다음 쪽 표시 |
| 바깥에서 준 조건이 먼저 걸린다 | 레지스트리가 다른 이미지 둘, 전역 역할 있음 | 한 레지스트리로 좁힌 조회 | 그 레지스트리의 것만 남는다 |
| 페이지 방식을 둘 섞어 준다 | 이미지 하나, 전역 역할 있음 | 크기와 커서를 함께 주고 조회 | 입력이 틀렸다는 이유로 거부 |
| 커서 값이 깨져 있다 | 이미지 하나, 전역 역할 있음 | 잘못된 커서로 조회 | 커서가 틀렸다는 이유로 거부 |
| 별칭을 검색한다 | 별칭 둘, 전역 역할 있음 | 별칭 조회 | 둘을 모두 센다 |
| 슈퍼관리자가 아닌 사용자가 별칭을 검색한다 | 전역 역할 없음 | 별칭 조회 | 역할로 거부 |

가운데 두 줄은 요청 타입이 막는 것이 아니다. 어댑터가 페이지 방식을 고르면서 낸다. 어댑터가
보장하는 것이므로 줄로 둔다.

바깥에서 준 조건은 커서를 읽는 검색에만 있다. 사용자가 준 필터보다 먼저 걸리므로 둘째 줄이 그
순서를 본다.

않고 요청 전체가 막힌다.

## 잊기와 되살리기

잊기는 행을 지우지 않는다. 상태만 지워진 것으로 바꾸므로 되살릴 수 있다. 행까지 없애는 것은
아래 지우기다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이미지를 잊는다 | 살아 있는 이미지, 전역 역할 있음 | 잊기 | 지워졌다는 상태를 실은 노드. 행은 남는다 |
| 커스텀 이미지의 주인이 자기 것을 잊는다 | 자기가 만든 커스텀 이미지, 그 이미지에 잊기 권한 있음 | 잊기 | 지워졌다는 상태를 실은 노드 |
| 잊은 것을 되살린다 | 잊힌 이미지, 전역 역할 있음 | 되살리기 | 이미지 없음으로 거부 |
| 잊지 않은 것을 되살린다 | 살아 있는 이미지, 전역 역할 있음 | 되살리기 | 살아 있는 그대로 |
| 아무것도 갖지 않은 id를 잊는다 | 다른 이미지만 있음, 전역 역할 있음 | 잊기 | 이미지 없음으로 거부 |
| 아무것도 갖지 않은 id를 되살린다 | 다른 이미지만 있음, 전역 역할 있음 | 되살리기 | 이미지 없음으로 거부 |
| 아무 권한도 받지 않은 사용자가 잊는다 | 커스터마이즈되지 않은 이미지, 아무 권한도 없음 | 잊기 | 권한 부족으로 거부 |
| 아무 권한도 받지 않은 사용자가 되살린다 | 커스터마이즈되지 않은 이미지, 아무 권한도 없음 | 되살리기 | 권한 부족으로 거부 |
| 권한을 받았어도 주인 없는 이미지는 잊지 못한다 | 커스터마이즈되지 않은 이미지, 그 이미지에 잊기 권한 있음 | 잊기 | 접근 금지로 거부 |
| 집행을 꺼도 주인 없는 이미지는 잊지 못한다 | 엔티티 권한 집행 꺼짐, 아무 권한도 없음, 커스터마이즈되지 않은 이미지 | 잊기 | 접근 금지로 거부 |
| 지우는 중인 이미지를 잊는다 | 지우는 중인 이미지, 전역 역할 있음 | 잊기 | 이미지 없음으로 거부 |

아홉째와 열째 줄이 이 어댑터의 핵심이다. 게이트를 지난 사람이 소유권 검사에서 막힌다. 집행을
꺼서 게이트를 열어도 그 검사는 그대로 돈다.

그래서 권한 부족과 접근 금지를 하나로 뭉치면 안 된다. 뭉치면 권한을 더 주면 되는지를 호출자가
알 수 없다.

출하된 이미지에는 주인이 없다. 슈퍼관리자 말고는 아무도 잊을 수 없다.

되살리기는 잊힌 이미지에 닿지 못한다. 이미지를 id로 집는 자리가 살아 있는 것만 보므로, 잊힌
것을 되살리려 하면 이미지가 없다고 답한다. 살아 있는 것을 되살리는 것만 성공하는데 그것은
아무것도 바꾸지 않는다. 지우는 중인 이미지도 같은 이유로 보이지 않아서, 상태 쓰기를 막는
검사에는 이 어댑터를 통해 닿을 수 없다.

되살리기가 이대로여도 되는지 정한다. 줄은 지금 일어나는 일을 적은 것이고, 고치면 두 줄이
함께 바뀐다.

| 아무것도 갖지 않은 id를 지운다 | 다른 이미지만 있음, 전역 역할 있음 | 지우기 | 이미지 없음으로 거부 |
| 아무 권한도 받지 않은 사용자가 지운다 | 같은 이미지, 아무 권한도 없음 | 지우기 | 권한 부족으로 거부 |

## 별칭 붙이고 떼기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 별칭을 붙인다 | 이미지 하나, 전역 역할 있음 | 별칭 붙이기 | 별칭 id와 이름, 그리고 그 이미지의 id |
| 붙인 별칭을 뗀다 | 별칭이 붙어 있음, 전역 역할 있음 | 별칭 떼기 | 떼어낸 별칭과 그 이미지의 id |
| 아무것도 갖지 않은 id에 별칭을 붙인다 | 다른 이미지만 있음, 전역 역할 있음 | 별칭 붙이기 | 이미지 없음으로 거부 |
| 이미 쓰이는 별칭을 붙인다 | 그 별칭이 다른 이미지에 붙어 있음, 전역 역할 있음 | 별칭 붙이기 | 유니크 제약 위반으로 거부 |
| 아무것도 갖지 않은 별칭을 뗀다 | 다른 별칭만 있음, 전역 역할 있음 | 별칭 떼기 | 별칭 없음으로 거부 |
| 슈퍼관리자가 아닌 사용자가 별칭을 붙인다 | 이미지 하나, 전역 역할 없음 | 별칭 붙이기 | 역할로 거부 |
| 슈퍼관리자가 아닌 사용자가 별칭을 뗀다 | 별칭이 붙어 있음, 전역 역할 없음 | 별칭 떼기 | 역할로 거부 |

별칭은 이미지의 필드다. 그런데 붙이고 떼는 문은 전역 역할이다. 이미지를 잊는 문과 달라서, 같은
이미지에 대해 두 문이 서로 다르게 거부한다. 커스텀 이미지의 주인이라도 자기 이미지에 별칭을
붙일 수는 없다.

## 고치기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 태그만 바꾼다 | 이미지 하나, 전역 역할 있음 | 태그 수정 | 태그는 새 값, 나머지는 그대로 |
| 값을 하나도 주지 않는다 | 이미지 하나, 전역 역할 있음 | 빈 수정 | 아무것도 바뀌지 않은 노드 |
| 가속기 목록을 비운다 | 가속기가 적힌 이미지, 전역 역할 있음 | 가속기를 비우는 수정 | 가속기 자리가 빈 노드 |
| 가속기 이름을 준다 | 가속기가 적히지 않은 이미지, 전역 역할 있음 | 가속기 이름을 주는 수정 | 그 이름이 적힌 노드 |
| 아무것도 갖지 않은 id를 고친다 | 다른 이미지만 있음, 전역 역할 있음 | 태그 수정 | 이미지 없음으로 거부 |
| 슈퍼관리자가 아닌 사용자가 고친다 | 같은 이미지, 전역 역할 없음 | 태그 수정 | 역할로 거부 |

가속기 목록만 세 갈래를 받는다. 생략하거나, 비우거나, 값을 준다. 나머지 항목은 생략과 값
주기 둘뿐이라 셋째 줄은 가속기에만 둔다.

## 답이 행위자에 따라 달라진다

에이전트 설치 정보를 가리는 설정이 있다. 켜져 있으면 슈퍼관리자가 아닌 호출자에게는 그 정보가
빈 채로 온다.

같은 이미지를 같은 요청으로 읽어도 답이 갈린다는 뜻이다. 그래서 검색의 성공 줄을 행위자마다
따로 세운다. 이 갈림은 이 어댑터에만 있다.

## 아직 적지 않은 것

이 어댑터가 자기 이름으로 내놓는 열한 호출은 모두 위에 있다.

답에 실리지 않는 변화는 이 표가 보지 못한다. 지우기가 별칭까지 데려가는 것이 그렇다. 답은
지워진 이미지뿐이고, 별칭이 남았는지 확인하려면 그다음 읽기가 필요하다. 시나리오 한 줄이
호출 하나를 두고 짝을 세우는 자리이므로 그 읽기는 여기 오지 않는다.

`batch_load_fields`는 아직 아무 시나리오도 부르지 않는다. 어댑터 공통 바탕이 내놓는 것이고,
필드 행을 DataLoader로 읽는 자리라 이미지의 어느 필드를 읽을지 정한 뒤에 적는다.
