# 이미지 adapter 는 이미지 요청과 응답을 변환한다

규칙은 상위 디렉터리의 `AGENTS.md` 에 있다. 이 문서와 실행 결과가 다르면 문장을 먼저 의심한다.

호출을 차단하는 검사는 superadmin 검사, 이미지 권한 검사, 컨테이너 레지스트리 권한 검사, 커스텀 이미지 작성자 검사다.

| 검사 | 적용되는 호출 | 확인하는 것 |
|---|---|---|
| superadmin 검사 | 검색, 별칭 | 호출자가 superadmin 인지 |
| 이미지 권한 검사 | 수정, 삭제, 복원, 영구 삭제, 여러 ID 조회(ID 마다), 여럿 수정/삭제/복원(ID 마다), 한 이미지의 별칭 검색 | 호출자가 해당 이미지의 권한을 받았는지 |
| 컨테이너 레지스트리 권한 검사 | 한 컨테이너 레지스트리를 스코프로 하는 이미지 검색 | 호출자가 해당 컨테이너 레지스트리의 권한을 받았는지 |
| 커스텀 이미지 작성자 검사 | 영구 삭제 | 이미지가 커스텀 이미지이고 호출자가 생성했는지 |

영구 삭제에서는 이미지 권한 검사와 커스텀 이미지 작성자 검사가 차례로 실행된다. 이미지 권한 검사를 통과해도 커스텀 이미지 작성자 검사가 남는다.

`image` 엔티티는 컨테이너 레지스트리에 속한다. 세션 커밋으로 생성한 커스텀 이미지는 커밋한 사용자의 개인 프로젝트에도 속하므로, 그 개인 프로젝트에서 받은 이미지 권한이 그 이미지에 적용된다. 컨테이너 레지스트리 자체의 시나리오는 `../container_registry/KNOWLEDGE.md` 에 있다.

## 검색

요청 타입은 크기와 오프셋, 커서를 모두 받지만 한 요청에는 한 방식만 사용한다. 둘을 함께 지정하면 잘못된 입력으로 거부된다. 크기와 커서를 모두 생략하면 오프셋으로 50개를 읽는다.

커서를 사용하는 검색은 이미지 검색과 별칭 검색으로 따로 있다.

별칭 검색은 두 가지다. 전체 별칭 검색은 superadmin 검사가 차단하고, 한 이미지의 별칭 검색은 그 이미지의 권한 검사가 차단한다. 같은 일반 사용자라도 거부 이유가 다르다.

크기와 커서를 함께 지정하거나 커서 값이 잘못된 경우의 거부는 요청 타입이 차단하지 않는다. adapter 가 페이지 방식을 고르는 과정에서 발생한다. adapter 가 보장하는 동작이므로 시나리오로 남긴다.

이미지 검색도 두 가지다. 스코프 없는 검색은 superadmin 검사가 차단하고, 한 컨테이너 레지스트리를 스코프로 하는 검색은 그 컨테이너 레지스트리의 권한 검사가 차단한다.

## 여러 ID 로 조회

여러 ID 조회는 요청 전체가 아니라 ID 마다 이미지 권한 검사를 거친다. 거부된 ID 위치에는 예외 객체가 반환되고, 나머지 ID 위치에는 조회 결과가 그대로 반환된다.

## 삭제와 복원

삭제는 row 를 제거하지 않는다. 상태만 `DELETED` 값으로 변경하므로 복원할 수 있다. row 까지 제거하는 것은 아래의 영구 삭제다.

삭제와 복원은 이미지 권한 검사만 거친다. 커스텀 이미지가 아니어도 권한을 받은 사용자는 삭제할 수 있다.

삭제는 `ALIVE` 상태인 이미지에 적용된다. 복원은 `DELETED` 상태인 이미지와 `ALIVE` 상태인 이미지 모두에 적용되고, `ALIVE` 상태인 이미지를 복원하면 아무것도 변경되지 않는다. 그 밖의 상태는 대상을 찾을 수 없어 거부된다.

수정, 삭제, 복원은 id 를 받는다. body 에 id 를 담는 옛 REST 경로는 같은 호출로 이어진다.

## 여럿 삭제와 복원

여럿 연산은 호출 전체를 거부하지 않는다. 처리한 이미지는 처리된 목록에, 처리하지 못한 항목은 id 와 이유를 실패 목록에 담는다. 여럿 영구 삭제는 없다.

## 영구 삭제

이미지 권한 검사의 거부(권한 부족)와 커스텀 이미지 작성자 검사의 거부(접근 금지)를 하나로 합치면 안 된다. 합치면 권한을 더 받으면 해결되는 상황인지를 호출자가 구분할 수 없다.

커스텀 이미지가 아니면 작성자 검사를 통과할 수 없다. superadmin 만 이 검사를 건너뛰고 영구 삭제할 수 있다. 이는 이미지와 컨테이너 레지스트리의 RBAC own 관계를 의미하지 않는다.

## 별칭 등록과 해제

별칭은 이미지에 속한 값이다. 등록과 해제는 이미지 권한이 아니라 superadmin 검사가 차단한다. 삭제는 이미지 권한 검사가, 별칭 등록은 superadmin 검사가 차단하므로 같은 이미지라도 거부 이유가 다르다. "커스텀 이미지 작성자가 자기 이미지에 별칭을 등록한다"가 그 차이를 확인한다. 커스텀 이미지 작성자라도 자기 이미지에 별칭을 등록할 수는 없다.

## 수정

생략, 비우기, 값 지정을 구분하는 것은 `supported_accelerators` 필드뿐이다. 나머지 필드는 생략과 값 지정만 받으므로 비우는 시나리오는 `supported_accelerators` 필드에만 둔다.
