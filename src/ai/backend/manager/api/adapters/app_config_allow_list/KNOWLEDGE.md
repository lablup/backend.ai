# app_config_allow_list 어댑터의 현재 계약

허용 목록 항목은 등록된 설정 이름을 특정 스코프 유형에서 사용할 수 있게 한다. 각 항목의
순위는 여러 스코프의 설정 조각을 병합할 때 적용할 우선순위를 정한다.

- 허용 목록 항목은 도메인·프로젝트·사용자 스코프에 자동 귀속되지 않는다.
- 생성과 전체 검색에는 RBAC 강제 여부와 무관하게 슈퍼관리자 검사가 적용된다.
- 개별 조회, 배치 조회, 수정, 영구 삭제에는 허용 목록 엔티티에 대한 권한 검사가 적용된다.
- 현재 기본 역할이 앉을 수 있는 스코프에서 허용 목록 항목까지 이어지는 소유 관계가 없으므로,
  RBAC 강제가 켜져 있으면 일반 사용자는 개별 엔티티 권한 검사도 통과하지 못한다.

허용 목록 항목을 만들 때 RBAC 노드 자체는 생성된다. 따라서 “허용 목록 항목은 RBAC 엔티티가
아니다”가 아니라 “현재 도메인·프로젝트·사용자 소유 관계에 연결되지 않는다”가 정확한 설명이다.

순위는 설정 조각이 아니라 허용 목록 항목에 있다. 설정 값을 작성할 수 있는 사용자는 자기 설정
조각의 순위를 바꿀 수 없다. 실제 병합 계약은 [app_config 어댑터](../app_config/KNOWLEDGE.md)가
다룬다.

## 생성은 슈퍼관리자에게만 열려 있다

| 상황 | 요청 | 결과 |
|---|---|---|
| 슈퍼관리자 | 순위를 생략하고 PUBLIC 항목 생성 | 순위 100 |
| 슈퍼관리자 | 순위를 생략하고 DOMAIN 항목 생성 | 순위 200 |
| 슈퍼관리자 | 순위를 생략하고 USER 항목 생성 | 순위 300 |
| 슈퍼관리자 | 순위 250을 지정해 DOMAIN 항목 생성 | 순위 250 |
| 슈퍼관리자 | 등록되지 않은 설정 이름으로 생성 | `AppConfigDefinitionNotFound` |
| 슈퍼관리자 | 같은 설정 이름과 스코프 유형으로 다시 생성 | `UniqueConstraintViolationError` |
| 일반 사용자 | 항목 생성 | `InsufficientPrivilege` |
| RBAC 강제 비활성화, 일반 사용자 | 항목 생성 | `InsufficientPrivilege` |

순위를 생략하면 스코프 유형별 기본값을 사용한다. 100 단위의 간격은 관리자가 기존 기본값
사이에 별도 순위를 지정할 수 있게 한다.

등록되지 않은 설정 이름은 도메인 오류로 변환한다. 중복 항목은 아직 별도 도메인 오류로
변환하지 않아 데이터베이스 제약 오류로 응답한다.

## 개별 조회는 엔티티 읽기 권한을 검사한다

| 상황 | 요청 | 결과 |
|---|---|---|
| 슈퍼관리자 | 존재하는 ID 조회 | 항목의 모든 필드 반환 |
| 권한이 없는 일반 사용자 | 존재하는 ID 조회 | `NotEnoughPermission` |
| 슈퍼관리자 | 존재하지 않는 ID 조회 | `EntityNotFoundError` |
| RBAC 강제 비활성화, 일반 사용자 | 존재하는 ID 조회 | 항목의 모든 필드 반환 |

권한 검사가 데이터 조회보다 먼저 실행된다. 따라서 권한이 없는 사용자는 존재하지 않는 ID를
요청해도 대상 없음이 아니라 권한 오류를 받는다.

## 배치 조회는 입력 위치마다 결과를 반환한다

| 상황 | 요청 | 결과 |
|---|---|---|
| 슈퍼관리자 | 존재하는 ID 둘과 없는 ID 하나 | 두 노드와 `None`을 입력 순서대로 반환 |
| 슈퍼관리자 | 같은 ID 두 번 | 같은 노드를 두 위치에 반환 |
| 권한이 없는 일반 사용자 | 존재하는 ID 둘과 없는 ID 하나 | 각 위치에 `NotEnoughPermission` 반환 |
| 일반 사용자 | 빈 목록 | 빈 목록 반환 |

한 ID의 권한 실패는 배치 전체를 중단하지 않는다. 존재하지 않는 ID가 `None`인지 권한 오류인지는
그 ID에 대한 권한 검사를 먼저 통과했는지에 따라 달라진다.

## 전체 검색은 슈퍼관리자에게만 열려 있다

| 상황 | 요청 | 결과 |
|---|---|---|
| 슈퍼관리자 | 필터 없음 | 모든 항목과 전체 개수 반환 |
| 일반 사용자 | 검색 | `InsufficientPrivilege` |

필터·정렬·페이지네이션은 검색 공통 계약이라 이 어댑터의 시나리오로 검증하지 않는다.

## 수정할 수 있는 필드는 순위뿐이다

| 상황 | 요청 | 결과 |
|---|---|---|
| 슈퍼관리자 | 새 순위 지정 | 순위만 변경된 항목 반환 |
| 슈퍼관리자 | 빈 수정 요청 | 변경되지 않은 항목 반환 |
| 권한이 없는 일반 사용자 | 순위 수정 | `NotEnoughPermission` |
| 슈퍼관리자 | 존재하지 않는 ID 수정 | `EntityNotFoundError` |

설정 이름과 스코프 유형은 수정 요청 DTO에 없다. 이 둘을 바꾸려면 기존 항목을 삭제하고 새
항목을 생성해야 한다.

## 영구 삭제는 항목 행과 RBAC 노드를 제거한다

| 상황 | 요청 | 결과 |
|---|---|---|
| 슈퍼관리자 | 설정 조각이 없는 항목 영구 삭제 | 삭제한 항목의 ID 반환 |
| 슈퍼관리자 | 설정 조각이 있는 항목 영구 삭제 | 설정 조각이 막지 않고 항목의 ID 반환 |
| 권한이 없는 일반 사용자 | 항목 영구 삭제 | `NotEnoughPermission` |
| 슈퍼관리자 | 존재하지 않는 ID 영구 삭제 | `EntityNotFoundError` |

허용 목록 항목 행을 삭제하면 외래 키 연쇄 삭제로 그 아래 설정 조각도 사라진다. 허용 목록 항목
자체의 RBAC 노드는 영구 삭제 경로가 정리한다. soft delete와 복원 호출은 없다.

현재 영구 삭제 경로는 데이터베이스가 연쇄 삭제한 설정 조각의 RBAC 노드까지 정리하지 않는다.
이 잔존 노드는 보장할 동작이 아니라 별도 수정이 필요한 한계다. 시나리오는 어댑터 응답을
검증하며, 연쇄 삭제된 행과 잔존 RBAC 노드는 직접 조회하지 않는다.
