# 런타임 변형 preset 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 내용과 실행 결과가 어긋나면 문장 쪽을 먼저
의심한다.

preset은 변형 하나에 딸리지만 변형의 스코프에 만들어지지는 않는다. 변형을 컬럼으로 참조할 뿐
어느 스코프에도 속하지 않으므로, 권한 경로는 변형과 같다 — 생성은 전역 역할, 수정과 삭제는 그
preset에 부여된 권한인데 그 권한을 받을 방법이 없다. 조회와 검색은 인증만 확인한다.

변형 자체의 호출은 `../runtime_variant/KNOWLEDGE.md`에 있다.

## 생성

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필수 항목만 지정해 생성한다 | 변형 하나, 그 변형에 preset 없음, 전역 역할 있음 | 변형·이름·대상·값 종류·키로 생성 | 순위는 100, 필수 여부는 거짓, 나머지 선택 항목은 비어 있는 노드 |
| 같은 변형에 하나 더 생성한다 | 그 변형에 preset 하나, 전역 역할 있음 | 생성 | 순위가 앞의 것보다 100 크다 |
| 대상·값 종류·기본값·키를 따로 지정해 생성한다 | 변형 하나, 전역 역할 있음 | 네 값을 지정해 생성 | 응답에서는 넷이 한 명세로 묶여 반환된다 |
| 값 종류마다 맞는 기본값을 지정해 생성한다 | 변형 하나, 전역 역할 있음 | 다섯 값 종류 각각에 맞는 기본값으로 생성 | 생성된다 |
| UI 옵션을 지정해 생성한다 | 변형 하나, 전역 역할 있음 | 슬라이더 옵션을 붙여 생성 | UI 종류가 옵션에서 읽혀 노드에 함께 담긴다 |
| 같은 변형 안에서 이름이 중복된다 | 그 변형에 같은 이름의 preset, 전역 역할 있음 | 생성 | 이름 중복으로 거부 |
| 변형이 다르면 같은 이름을 쓸 수 있다 | 변형 둘, 한쪽에 preset 하나, 전역 역할 있음 | 다른 변형에 같은 이름으로 생성 | 생성된다 |
| 슈퍼관리자가 아닌 사용자가 생성한다 | 변형 하나, 전역 역할 없음 | 생성 | 역할 부족으로 거부 |
| 권한 검사를 꺼도 슈퍼관리자가 아니면 생성할 수 없다 | 권한 검사 비활성화, 전역 역할 없음 | 생성 | 역할 부족으로 거부 |

순위는 요청으로 정할 수 없다. 생성이 같은 변형 안의 가장 큰 순위에 100을 더해 넣고, 첫
preset은 100이 된다. 두 번째 시나리오가 그 간격을 검사한다.

UI 종류는 요청에 없고 UI 옵션에서 읽힌다. 옵션을 지정한 시나리오에서는 함께 담기고, 첫
시나리오처럼 옵션을 생략하면 함께 비어 있다.

flag 값 종류를 args가 아닌 대상에 두는 요청과, 값 종류에 맞지 않는 기본값은 시나리오로 두지
않는다. 생성할 때는 요청 타입이 막으므로 어댑터가 보장하는 것이 아니다. 같은 두 규칙을 수정할
때는 서비스가 저장된 값과 합쳐 다시 검사하므로, 그쪽에는 시나리오를 둔다.

존재하지 않는 변형 id로 생성하는 시나리오는 아직 두지 않는다. preset의 변형 컬럼에 외래 키가
마이그레이션에는 있고 ORM에는 없어, 마이그레이션으로 만든 데이터베이스에서는 거부되고 스키마를
한 번에 만든 데이터베이스에서는 생성된다. 어느 쪽이 맞는지 정한 뒤 시나리오를 적는다.

## 조회

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 아무 권한도 없는 사용자가 id로 조회한다 | preset 하나, 아무 권한도 없음 | id로 조회 | 그 preset 전체 |
| 존재하지 않는 id로 조회한다 | 다른 preset만 있음 | id로 조회 | 대상을 찾을 수 없어 거부 |
| 있는 것과 없는 것을 섞어 조회한다 | preset 둘, 아무 권한도 없음 | 세 id를 한 번에 | 목록 순서대로, 없는 id 자리는 비어서 반환된다 |
| 빈 목록을 준다 | preset 하나 | 빈 id 목록 | 빈 응답. 하위 계층을 호출하지 않는다 |

조회에는 권한 검사가 없다. 아무 권한도 없는 사용자가 성공하는 시나리오가 그것을 증명하므로 이
절에는 거부 짝이 없고, 짝은 생성 절의 역할 부족으로 거부되는 시나리오다.

여러 id로 조회하기는 검색을 id 조건으로 호출한 것이다. 원소마다 응답하는 조회가 아니므로 없는
id가 거부가 아니라 빈 항목으로 반환된다.

인증되지 않은 호출은 시나리오로 두지 않는다. 시나리오는 언제나 미리 만들어 둔 사용자로 호출한다.

## 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 아무 권한도 없는 사용자가 검색한다 | preset 둘, 아무 권한도 없음 | 전체 조회 | 둘 다 집계된다 |
| 변형 필터로 검색한다 | 변형 둘에 preset이 나뉘어 있음 | 변형 필터 조회 | 그 변형의 preset만 남는다 |
| 런타임 버전 필터로 검색한다 | 추가 버전과 폐기 버전이 다른 preset 여럿 | 버전 필터 조회 | 그 버전에 유효한 preset만 남는다 |
| 페이지 크기를 생략한다 | preset 11개 | 크기 없이 조회 | 10건까지 반환되고 다음 페이지가 있다고 응답한다 |

버전 필터는 추가 버전 이상, 폐기 버전 미만인 것을 남긴다. 어느 한쪽이 비어 있으면 그쪽은 제한이
없다. 세 번째 시나리오는 네 가지 — 둘 다 있음, 추가만 있음, 폐기만 있음, 둘 다 없음 — 를 함께
만들어 두고 검사한다.

## 수정

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이름만 바꾼다 | preset 하나, 전역 역할 있음 | 이름 수정 | 이름은 새 값, 나머지는 그대로 |
| 설명을 지운다 | 설명이 있는 preset, 전역 역할 있음 | 설명을 비우는 수정 | 설명이 없어진다 |
| 순위를 바꾼다 | preset 하나, 전역 역할 있음 | 순위 수정 | 순위가 새 값인 노드 |
| 값을 하나도 지정하지 않는다 | preset 하나, 전역 역할 있음 | 빈 수정 | 아무것도 바뀌지 않은 노드 |
| 값 종류만 flag로 바꾼다 | 대상이 env인 preset, 전역 역할 있음 | 값 종류를 flag로 수정 | 잘못된 입력으로 거부 |
| 기본값만 바꿔 값 종류와 어긋나게 한다 | 값 종류가 정수인 preset, 전역 역할 있음 | 기본값을 숫자 아닌 문자열로 수정 | 잘못된 입력으로 거부 |
| 존재하지 않는 id를 수정한다 | 다른 preset만 있음, 전역 역할 있음 | 이름 수정 | 대상을 찾을 수 없어 거부 |
| 아무 권한도 없는 사용자가 수정한다 | 같은 preset, 아무 권한도 없음 | 이름 수정 | 권한 부족으로 거부 |
| 권한 검사를 끄면 권한 없이도 수정된다 | 권한 검사 비활성화, 아무 권한도 없음 | 이름 수정 | 이름이 새 값인 노드 |

다섯 번째와 여섯 번째 시나리오는 요청 타입이 막는 것이 아니다. 요청은 대상을 생략했고 기본값만
지정했으므로 요청 타입은 통과시키고, 서비스가 저장된 행과 합쳐 검사한 뒤 막는다. 생성할 때와
같은 규칙이 다른 위치에서 다른 오류로 거부되므로 따로 시나리오를 둔다.

값 종류만 바꾸는 요청은 저장된 기본값을 다시 검사하지 않는다. 지금은 기본값이 새 값 종류와
어긋난 채 수정된다. 시나리오를 적기 전에 막을 것인지 정한다.

## 삭제

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 삭제한다 | preset 하나, 전역 역할 있음 | 삭제 | 삭제한 id를 담은 응답 |
| 존재하지 않는 id를 삭제한다 | 다른 preset만 있음, 전역 역할 있음 | 삭제 | 대상을 찾을 수 없어 거부 |
| 아무 권한도 없는 사용자가 삭제한다 | 같은 preset, 아무 권한도 없음 | 삭제 | 권한 부족으로 거부 |
| 권한 검사를 끄면 권한 없이도 삭제된다 | 권한 검사 비활성화, 아무 권한도 없음 | 삭제 | 삭제한 id를 담은 응답 |

권한 검사를 끄는 시나리오가 생성 절과 반대 결과를 갖는다. 수정과 삭제는 역할이 아니라 권한
그래프로 보호되므로 스위치가 영향을 준다. 같은 스위치로 아무 권한 없는 사용자가 preset을
수정하고 삭제할 수 있게 되지만 생성할 수는 없다는 것이 이 어댑터의 차이점이다.

이 어댑터에는 soft delete가 없다.

## 아직 적지 않은 것

없다. 어댑터가 제공하는 여섯 호출이 모두 위에 있다.

`batch_load_fields`는 모든 어댑터가 물려받는 공용 도우미이지 이 엔티티의 호출이 아니다. 레포트가
함께 세지만 적을 것이 없다.
