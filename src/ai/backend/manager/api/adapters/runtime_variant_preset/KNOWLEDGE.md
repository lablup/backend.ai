# 런타임 변형 프리셋 어댑터 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 내용과 실행 결과가 어긋나면 문장을 먼저
검토한다.

프리셋은 변형에 속하지만 변형의 스코프 안에서 생성되지는 않는다. 변형을 열로 참조할 뿐 어느
스코프에도 속하지 않는다. 생성에는 전역 역할이 필요하다. 수정과 삭제에는 프리셋별 권한이
필요하지만 현재는 그 권한을 부여할 방법이 없다. 조회와 검색은 인증 여부만 확인한다.

변형 자체의 호출은 `../runtime_variant/KNOWLEDGE.md`에 있다.

## 생성

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필수 항목만 지정해 생성한다 | 변형 하나, 해당 변형에 프리셋이 없음, 전역 역할 보유 | 변형·이름·대상·값 종류·키로 생성 | 순위는 100이고, 필수 항목이 아니며, 나머지 선택 항목은 비어 있음 |
| 같은 변형에 하나 더 생성한다 | 해당 변형에 프리셋 하나, 전역 역할 보유 | 생성 | 새 프리셋의 순위가 기존 프리셋보다 100 큼 |
| 대상·값 종류·기본값·키를 모두 지정해 생성한다 | 변형 하나, 전역 역할 보유 | 네 값을 모두 지정하여 생성 | 네 값이 하나의 명세로 묶여 반환됨 |
| 값 종류마다 올바른 기본값을 지정해 생성한다 | 변형 하나, 전역 역할 보유 | `str`, `int`, `float`, `bool`, `flag` 값 종류에 각각 맞는 기본값으로 생성 | 생성됨 |
| UI 옵션을 지정해 생성한다 | 변형 하나, 전역 역할 보유 | 슬라이더 옵션을 추가하여 생성 | UI 종류를 옵션에서 읽어 응답 노드에 함께 담음 |
| 같은 변형 안에서 이름이 중복된다 | 해당 변형에 같은 이름의 프리셋이 있음, 전역 역할 보유 | 생성 | 이름 중복으로 요청이 거부됨 |
| 변형이 다르면 같은 이름을 쓸 수 있다 | 변형 둘, 한쪽에만 프리셋 하나, 전역 역할 보유 | 다른 변형에 같은 이름으로 생성 | 생성됨 |
| 슈퍼관리자가 아닌 사용자가 생성한다 | 변형 하나, 전역 역할 없음 | 생성 | 역할 부족으로 요청이 거부됨 |
| 권한 검사를 꺼도 슈퍼관리자가 아니면 생성할 수 없다 | 권한 검사 비활성화, 전역 역할 없음 | 생성 | 역할 부족으로 요청이 거부됨 |

순위는 요청에서 정할 수 없다. 생성 시 같은 변형에서 가장 큰 순위에 100을 더하며, 첫 프리셋의
순위는 100이 된다. 같은 변형에 프리셋을 하나 더 생성하는 시나리오에서 이 간격을 검사한다.

UI 종류는 요청에 별도 필드로 없으며 UI 옵션에서 읽는다. 옵션을 지정하면 응답에 함께 담기고,
필수 항목만 지정해 생성하는 시나리오처럼 옵션을 생략하면 UI 종류도 비어 있다.

값 종류가 `flag`인데 대상이 `args`가 아닌 요청과 값 종류에 맞지 않는 기본값은 생성 시나리오에
포함하지 않는다. 생성 요청 타입에서 거부하므로 어댑터가 보장하는 동작이 아니기 때문이다. 수정
시에는 서비스가 저장된 값과 요청을 합쳐 이 두 규칙을 다시 검사하므로 시나리오에 포함한다.

존재하지 않는 변형 ID로 생성하는 시나리오는 아직 포함하지 않는다. 프리셋의 변형 열에 외래 키가
마이그레이션에는 있지만 ORM에는 없다. 따라서 마이그레이션으로 만든 데이터베이스에서는 요청이
거부되지만 스키마를 한 번에 만든 데이터베이스에서는 생성된다. 올바른 동작을 정한 뒤 시나리오를
작성한다.

## 조회

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 아무 권한도 없는 사용자가 ID로 조회한다 | 프리셋 하나, 아무 권한도 없음 | ID로 조회 | 해당 프리셋 전체 |
| 존재하지 않는 ID로 조회한다 | 다른 프리셋만 있음 | ID로 조회 | 대상을 찾을 수 없어 요청이 거부됨 |
| 존재하는 ID와 존재하지 않는 ID를 함께 조회한다 | 프리셋 둘, 아무 권한도 없음 | 세 ID를 한 번에 조회 | 요청한 순서대로 반환되며, 존재하지 않는 ID는 빈 항목으로 반환됨 |
| 빈 목록으로 조회한다 | 프리셋 하나 | 빈 ID 목록으로 조회 | 빈 응답을 반환하고 하위 계층을 호출하지 않음 |

조회에는 권한 검사가 없다. 아무 권한도 없는 사용자의 조회가 성공하는 시나리오로 이를 검증한다.
반면 생성 요청은 전역 역할이 없으면 거부된다.

여러 ID 조회는 검색에 ID 조건을 지정하여 실행한다. 각 ID를 개별 조회하는 방식이 아니므로
존재하지 않는 ID가 있어도 요청 전체를 거부하지 않고 해당 위치에 빈 항목을 반환한다.

인증되지 않은 호출은 시나리오로 두지 않는다. 시나리오는 언제나 미리 만들어 둔 사용자로 호출한다.

## 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 아무 권한도 없는 사용자가 검색한다 | 프리셋 둘, 아무 권한도 없음 | 전체 조회 | 두 프리셋이 모두 반환됨 |
| 변형 필터로 검색한다 | 프리셋이 두 변형에 나뉘어 있음 | 변형 필터로 조회 | 해당 변형의 프리셋만 반환됨 |
| 런타임 버전 필터로 검색한다 | 추가 버전과 폐기 버전이 서로 다른 프리셋 여러 개 | 버전 필터로 조회 | 해당 버전에 유효한 프리셋만 반환됨 |
| 페이지 크기를 생략한다 | 프리셋 11개 | 페이지 크기 없이 조회 | 10건을 반환하고 다음 페이지가 있음을 표시함 |

버전 필터는 추가 버전 이상이고 폐기 버전 미만인 프리셋만 반환한다. 추가 버전이 비어 있으면 하한
제한이 없고, 폐기 버전이 비어 있으면 상한 제한이 없다. 런타임 버전 필터로 검색하는 시나리오에서는
두 버전이 모두 있는 경우, 추가 버전만 있는 경우, 폐기 버전만 있는 경우, 둘 다 없는 경우를 함께
검사한다.

## 수정

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이름만 바꾼다 | 프리셋 하나, 전역 역할 보유 | 이름 수정 | 이름만 변경되고 나머지는 유지됨 |
| 설명을 지운다 | 설명이 있는 프리셋, 전역 역할 보유 | 설명을 비우도록 수정 | 설명이 없어짐 |
| 순위를 바꾼다 | 프리셋 하나, 전역 역할 보유 | 순위 수정 | 순위가 변경된 노드 |
| 변경할 값을 지정하지 않는다 | 프리셋 하나, 전역 역할 보유 | 빈 수정 요청 | 아무것도 바뀌지 않은 노드 |
| 값 종류만 `flag`로 바꾼다 | 대상이 `env`인 프리셋, 전역 역할 보유 | 값 종류를 `flag`로 수정 | 잘못된 입력으로 요청이 거부됨 |
| 기본값만 바꿔 값 종류와 어긋나게 한다 | 값 종류가 정수인 프리셋, 전역 역할 보유 | 기본값을 숫자가 아닌 문자열로 수정 | 잘못된 입력으로 요청이 거부됨 |
| 존재하지 않는 ID를 수정한다 | 다른 프리셋만 있음, 전역 역할 보유 | 이름 수정 | 대상을 찾을 수 없어 요청이 거부됨 |
| 아무 권한도 없는 사용자가 수정한다 | 해당 프리셋에 아무 권한도 없음 | 이름 수정 | 권한 부족으로 요청이 거부됨 |
| 권한 검사를 끄면 권한 없이도 수정된다 | 권한 검사 비활성화, 아무 권한도 없음 | 이름 수정 | 이름이 변경된 노드 |

값 종류만 `flag`로 바꾸는 요청에는 대상이 없고, 기본값만 문자열로 바꾸는 요청에는 값 종류가
없다. 따라서 요청 타입만으로는 저장된 값과의 조합을 검증할 수 없다. 두 요청 모두 타입 검증을
통과하지만 서비스가 저장된 행과 요청을 합쳐 검사한 뒤 거부한다. 값 종류가 `flag`이면 대상이
`args`여야 하고 기본값은 값 종류에 맞아야 한다는 규칙을 생성 요청은 요청 타입에서, 수정 요청은
서비스에서 검사하므로 별도 시나리오로 둔다.

값 종류만 바꾸는 요청은 저장된 기본값을 다시 검사하지 않는다. 현재는 기본값이 새 값 종류와
어긋난 상태로 수정된다. 이를 거부할지 정한 뒤 시나리오를 작성한다.

이 어댑터는 소프트 삭제를 지원하지 않는다.

## 아직 적지 않은 것

없다. 어댑터가 제공하는 `create`, `get`, `search`, `batch_load_by_ids`, `update`, `delete`가 모두 위에
있다.

`batch_load_fields`는 모든 어댑터가 상속받는 공용 도우미이며 이 엔티티의 호출이 아니다.
보고서의 호출 목록에는 포함되지만 별도로 작성할 시나리오는 없다.
