# 비밀 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 내용과 실행 결과가 어긋나면 문장 쪽을 먼저
의심한다.

이 어댑터는 자체 엔티티 행을 갖지 않는다. 저장된 비밀이 어느 키로 암호화돼 있는지 집계하는
상태 조회와, 그 비밀을 전부 쓰기 제공자로 다시 암호화하는 스캔 한 번이 전부다. 둘 다 전역 역할이
있어야 하는데, 상태 조회는 읽기 연산이라 모니터 역할도 통과하고 재암호화는 쓰기 연산이라
통과하지 못한다. 한 어댑터 안에서 그 차이를 보여 주는 유일한 짝이다.

집계 대상 비밀은 컬럼 하나, 키페어의 비밀 키다. 호출자도 키페어를 가지므로 집계에는 언제나
호출자의 비밀 키가 포함되고, 저장된 비밀이 하나도 없는 상황은 만들 수 없다.

키 풀은 시나리오가 조립해서 넣는 값이다. 외부 서비스는 없다 — 구현된 키 제공자는 설정에서 키를
읽는 것 하나뿐이고, 쓰기 제공자를 두지 않으면 새 값은 평문으로 저장된다.

## 상태 조회

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 상태를 조회한다 | 쓰기 제공자가 평문인 키 풀, 호출자를 포함해 사용자 둘 | 상태 조회 | 쓰기 제공자는 평문. 집계는 항목 하나 — 비밀 키 컬럼이 평문인 행 둘 |
| 서로 다른 키로 암호화된 비밀이 섞여 있다 | 설정 키 제공자를 쓰기 제공자로 둔 키 풀, 그 키로 암호화된 비밀 하나와 평문 하나 | 상태 조회 | 집계는 항목 둘 — 그 키로 암호화된 것 하나, 평문 하나 |
| 모니터 역할이 상태를 조회한다 | 같은 상황, 모니터 역할 | 상태 조회 | 슈퍼관리자와 같은 응답 |
| 슈퍼관리자가 아닌 사용자가 상태를 조회한다 | 전역 역할 없음 | 상태 조회 | 역할 부족으로 거부 |

집계는 제공자 종류와 키 id 순으로 정렬되어 반환된다. 실행마다 순서가 같으므로 그대로 비교한다.

## 재암호화

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 평문 비밀을 설정 키로 옮긴다 | 설정 키 제공자를 쓰기 제공자로 둔 키 풀, 평문 비밀 둘 | 재암호화 | 둘을 스캔해 둘을 다시 썼다는 응답. 함께 담긴 상태는 그 키로 암호화된 것 둘, 평문 없음 |
| 이미 그 키로 암호화된 것을 다시 옮긴다 | 같은 키 풀, 그 키로 암호화된 비밀 둘 | 재암호화 | 둘을 스캔해 둘을 다시 썼다는 응답. 상태는 그대로 그 키로 암호화된 것 둘 |
| 쓰기 제공자가 평문일 때 실행한다 | 쓰기 제공자가 평문인 키 풀, 평문 비밀 둘 | 재암호화 | 둘을 스캔해 둘을 다시 썼다는 응답. 상태는 그대로 평문 둘 |
| 암호화된 것을 평문으로 되돌린다 | 쓰기 제공자가 평문이고 설정 키 제공자는 읽기 전용인 키 풀, 그 키로 암호화된 비밀 하나 | 재암호화 | 하나를 스캔해 하나를 다시 썼다는 응답. 상태는 평문 하나 |
| 모니터 역할이 실행한다 | 모니터 역할 | 재암호화 | 역할 부족으로 거부 |
| 슈퍼관리자가 아닌 사용자가 실행한다 | 전역 역할 없음 | 재암호화 | 역할 부족으로 거부 |

스캔은 모든 행을 동일하게 다룬다. 이미 쓰기 제공자의 키로 암호화된 것도 새 데이터 키로 다시
쓰므로, 두 번째 시나리오에서 다시 쓴 수가 스캔한 수와 같다. 중간에 끊긴 스캔을 다시 실행해 이어
가는 것이 이 설계이고, 그래서 같은 요청을 두 번 실행해도 응답이 같다.

쓰기 제공자가 평문이면 스캔이 값을 평문으로 되돌린다. 세 번째와 네 번째 시나리오가 그 두
방향이다. 다시 쓴 수는 값이 바뀌었는지가 아니라 행을 다시 썼는지를 세므로, 평문에서 평문으로
다시 쓴 것도 센다.

모니터 역할의 두 시나리오가 이 어댑터의 요점이다. 같은 사용자가 상태는 조회할 수 있지만
재암호화는 실행하지 못한다.

## 아직 적지 않은 것

없다. 어댑터가 제공하는 두 호출이 모두 위에 있다.

`batch_load_fields`는 모든 어댑터가 물려받는 공용 도우미이지 이 엔티티의 호출이 아니다. 레포트가
함께 세지만 적을 것이 없다.
