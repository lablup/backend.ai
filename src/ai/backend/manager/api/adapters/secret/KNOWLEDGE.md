# 비밀 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 것과 실행 결과가 어긋나면 문장을 먼저
의심한다.

이 어댑터는 행을 갖지 않는다. 저장된 비밀을 어느 키가 쥐고 있는지 세는 상태 조회와, 그 비밀을
전부 쓰기 제공자로 다시 암호화하는 한 번의 훑기뿐이다. 둘 다 전역 역할이 지키고, 상태 조회는
읽기라 모니터 역할도 지나며 다시 암호화는 쓰기라 지나지 못한다. 한 어댑터 안에서 그 갈림을
보이는 유일한 짝이다.

세는 비밀은 하나의 컬럼, 키 쌍의 비밀 키다. 부르는 사람도 키 쌍을 가지므로 집계에는 언제나
부르는 사람의 것이 들어 있고, 저장된 비밀이 하나도 없는 상황은 세울 수 없다.

키 풀은 시나리오가 조립해 넣는 값이다. 외부 서비스는 없다 — 구현된 키 제공자는 설정에서 키를
읽는 것 하나뿐이고, 쓰기 제공자를 두지 않으면 새 값은 평문으로 저장된다.

## 상태 읽기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 상태를 읽는다 | 쓰기 제공자가 평문인 키 풀, 부르는 사람까지 사용자 둘 | 상태 조회 | 쓰기 제공자는 평문. 집계는 한 줄 — 비밀 키 컬럼을 평문으로 쥔 둘 |
| 키가 다른 비밀이 섞여 있다 | 설정 키 제공자를 쓰기 제공자로 둔 키 풀, 그 키로 암호화된 비밀 하나와 평문 하나 | 상태 조회 | 집계는 두 줄 — 그 키가 하나, 평문이 하나 |
| 모니터 역할이 상태를 읽는다 | 같은 상황, 모니터 역할 | 상태 조회 | 슈퍼관리자와 같은 답 |
| 슈퍼관리자가 아닌 사용자가 상태를 읽는다 | 전역 역할 없음 | 상태 조회 | 역할로 거부 |

집계는 제공자 종류와 키 id 순으로 정렬돼 온다. 실행마다 순서가 같으므로 그대로 비교한다.

## 다시 암호화하기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 평문 비밀을 설정 키로 옮긴다 | 설정 키 제공자를 쓰기 제공자로 둔 키 풀, 평문 비밀 둘 | 다시 암호화 | 둘을 훑어 둘을 다시 썼다는 답. 함께 실린 상태는 그 키가 둘을 쥐고 평문은 없다 |
| 이미 그 키에 있는 것을 다시 옮긴다 | 같은 키 풀, 그 키로 암호화된 비밀 둘 | 다시 암호화 | 둘을 훑어 둘을 다시 썼다는 답. 상태는 그대로 그 키가 둘 |
| 쓰기 제공자가 평문일 때 돌린다 | 쓰기 제공자가 평문인 키 풀, 평문 비밀 둘 | 다시 암호화 | 둘을 훑어 둘을 다시 썼다는 답. 상태는 그대로 평문 둘 |
| 암호화된 것을 평문으로 되돌린다 | 쓰기 제공자가 평문이고 설정 키 제공자는 읽기용으로만 있는 키 풀, 그 키로 암호화된 비밀 하나 | 다시 암호화 | 하나를 훑어 하나를 다시 썼다는 답. 상태는 평문 하나 |
| 모니터 역할이 돌린다 | 모니터 역할 | 다시 암호화 | 역할로 거부 |
| 슈퍼관리자가 아닌 사용자가 돌린다 | 전역 역할 없음 | 다시 암호화 | 역할로 거부 |

훑기는 모든 행을 같게 다룬다. 이미 쓰기 제공자의 키에 있는 것도 새 데이터 키로 다시 쓰므로,
둘째 줄에서 다시 쓴 수가 훑은 수와 같다. 중간에 끊긴 훑기를 다시 돌려 이어 가는 것이 이
설계이고, 그래서 같은 요청을 두 번 돌려도 답이 같다.

쓰기 제공자가 평문이면 훑기가 값을 평문으로 되돌린다. 셋째와 넷째 줄이 그 두 방향이다. 다시
쓴 수는 값이 바뀌었는지가 아니라 행을 다시 썼는지를 세므로, 평문에서 평문으로도 센다.

모니터 역할의 두 줄이 이 어댑터의 요점이다. 같은 사람이 상태는 읽고 훑기는 돌리지 못한다.

## 아직 적지 않은 것

없다. 어댑터가 내놓는 두 호출이 모두 위에 있다.

`batch_load_fields`는 모든 어댑터가 물려받는 공용 도우미이지 이 엔티티의 호출이 아니다. 레포트가
함께 세지만 적을 것이 없다.
