# 자원 정책 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 내용과 실행 결과가 어긋나면 문장 쪽을 먼저
의심한다.

어댑터 하나가 프로젝트 정책, 키페어 정책, 사용자 정책 세 종류를 다룬다. 정책 종류마다 절을
하나씩 두고, 같은 호출이라도 절마다 따로 적는다. 아래 세 문단은 세 절에 공통이다.

정책은 어느 스코프에도 속하지 않게 만들어지므로 개별 정책에 권한을 부여할 수 없다. 생성과 전체
검색은 전역 superadmin 역할이 있어야 하고, 이름으로 조회·수정·삭제하는 호출은 권한 그래프가
검사하지만 그래프에서 정책에 도달하는 역할이 없으므로 결국 슈퍼관리자만 통과한다.

정책은 id가 아니라 이름으로 지정한다. 이름을 정책으로 풀어내는 단계가 먼저 실행되고, 존재하지
않는 이름과 권한이 미치지 않는 이름을 같은 이유("찾을 수 없음")로 거부한다. 슈퍼관리자에게도
동일하므로 이 어댑터에는 권한 부족과 구분되는 "대상 없음" 시나리오가 없다. 도메인과 반대다.
권한 없는 사용자는 수정·삭제 호출에 이르기 전에 이 단계에서 막히므로, 그 두 거부도 조회와 같은
이유로 온다.

이름 중복과 아직 사용 중인 정책의 삭제는 spec이 아니라 데이터베이스 제약이 막는다. spec이 그
위반에 별도 이름을 붙여 두지 않아 저장소가 제약 위반을 그대로 전파하므로, 그 거부는 정책 고유의
오류가 아니라 저장소의 제약 위반 오류로 온다. 이름이 공백뿐인 요청은 어느 절에도 시나리오로
두지 않는다. 요청 타입이 이미 막으므로 어댑터가 보장하는 것이 아니기 때문이다.

## 사용자 정책

생성할 때 생략할 수 있는 항목이 하나(동시 로그인 수)이고, 수정할 때 비울 수 있는 항목도 그
하나다. 자기 정책 조회는 사용자 행이 가리키는 정책을 그대로 읽는다.

### 생성

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 모든 값을 지정해 생성한다 | 정책 없음 | 생성 | 지정한 값이 그대로 담긴 노드 전체 |
| 동시 로그인 수를 생략하고 생성한다 | 정책 없음 | 동시 로그인 수 없이 생성 | 그 필드가 비어 있는 노드 전체 |
| 이미 사용 중인 이름으로 생성한다 | 그 이름의 정책이 있음 | 생성 | 이름 중복으로 거부 |
| 슈퍼관리자가 아닌 사용자가 생성한다 | 권한 없음 | 생성 | 역할 부족으로 거부 |
| 모니터 역할 사용자가 생성한다 | 모니터 역할 | 생성 | 역할 부족으로 거부 |
| 권한 검사를 꺼도 슈퍼관리자가 아니면 생성할 수 없다 | 권한 검사 비활성화 | 생성 | 역할 부족으로 거부 |

크기 한도는 사람이 읽기 쉬운 표기("1g")로 받고, 정확한 바이트 수와 읽기 쉬운 표기 둘 다로
응답한다.

### 이름으로 조회

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이름으로 조회한다 | 그 이름의 정책이 있음 | 이름으로 조회 | 그 정책 전체 |
| 아무 권한도 없는 사용자가 조회한다 | 같은 정책이 있음 | 이름으로 조회 | 정책을 찾을 수 없다는 이유로 거부 |
| 슈퍼관리자가 없는 이름으로 조회한다 | 다른 정책만 있음 | 이름으로 조회 | 정책을 찾을 수 없다는 이유로 거부 |
| 권한 검사를 끄면 권한 없이도 조회할 수 있다 | 권한 검사 비활성화, 권한 없음 | 이름으로 조회 | 그 정책 전체 |

### 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필터 없이 검색한다 | 정책 여럿이 있음 | 전체 검색 | 미리 만들어 둔 정책이 모두, 그리고 그것만 반환된다 |
| 이름 필터로 검색한다 | 이름이 다른 정책 여럿 | 이름 필터 검색 | 그 이름의 정책만 반환된다 |
| 모니터 역할 사용자가 검색한다 | 모니터 역할, 정책 하나 | 전체 검색 | 슈퍼관리자와 같은 응답 |
| 슈퍼관리자가 아닌 사용자가 검색한다 | 권한 없음 | 전체 검색 | 역할 부족으로 거부 |

### 수정

### 자기 정책 조회

요청 본문이 없고 호출자 자신이 곧 입력이다. 사용자 행은 정책 이름을 비워 둘 수 없으므로
사용자가 있으면 정책도 반드시 있다. 그래서 "대상 없음" 시나리오가 없다.

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 읽기 권한을 받은 사용자가 자기 정책을 조회한다 | 정책 하나, 그 정책이 할당된 사용자, 그 사용자 자신의 스코프에 사용자 정책 읽기 권한 있음 | 내 사용자 정책 조회 | 그 정책 전체 |
| 읽기 권한이 없는 사용자가 자기 정책을 조회한다 | 같은 사용자, 권한 없음 | 내 사용자 정책 조회 | 권한 부족으로 거부 |
| 권한 검사를 끄면 권한 없이도 자기 정책을 조회할 수 있다 | 권한 검사 비활성화, 권한 없음 | 내 사용자 정책 조회 | 그 정책 전체 |

## 아직 적지 않은 것

사용자 정책의 여섯 호출은 모두 위에 적혀 있다. 프로젝트 정책의 다섯 호출과 키페어 정책의 여섯
호출은 아직 절이 없다. 실행 결과가 그 목록을 함께 출력한다.

실행 결과에 남는 `batch_load_fields`는 모든 어댑터가 물려받는 공통 호출이고, 이 어댑터는
사용하지 않는다.
