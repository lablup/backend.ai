# login_client_type adapter: 배경

규칙은 상위 디렉터리의 `AGENTS.md` 에 있다. 이 문서와 실행 결과가 어긋나면 문장을 먼저 의심한다.

`login_client_type` 엔티티는 global 과 public 양쪽에 속한다. 생성은 호출한 사용자가 superadmin 인지 검사하고, id 로 수정하거나 영구 삭제하는 호출은 그 `login_client_type` row 에 부여된 권한을 검사하는데 그 권한은 global 에서만 나온다. 생성, 수정, 영구 삭제 모두 superadmin 만 성공하지만 거부 이유가 서로 다르다. 조회와 검색은 public 에서 READ 를 검사한다. 모든 계정이 public 소속 역할을 자동으로 받으므로 로그인한 사용자는 모두 읽을 수 있다.

## 생성

이름이 비어 있거나 길이 제한을 넘는 요청은 시나리오로 두지 않는다. 요청 타입이 이미 차단하기 때문이다.

## 조회

조회는 public 에서 READ 를 검사한다. public 조회 권한만 받은 사용자가 성공하는 시나리오가 그것을 증명하고, 대응하는 거부 시나리오는 생성 절에서 역할 부족으로 거부되는 시나리오다. 존재하지 않는 id 와 접근할 수 없는 id 는 같은 이유로 거부된다.

인증되지 않은 호출은 시나리오로 두지 않는다. 시나리오는 항상 미리 저장한 사용자로 호출한다.

## 검색

이름 필터가 무엇을 좁히는지와 페이지 방식(기본 크기 50, `first` 만 지정한 요청을 커서로 읽는지, BA-7927)은 시나리오로 두지 않는다. 필터를 조건으로 옮기고 페이지를 자르는 것은 단위 테스트에서 다룬다.

## 수정

수정은 대상 id 를 요청 본문 밖에서 별도 인자로 받는다. 시나리오가 id 를 인자와 본문에 거듭 적지 않도록 이 구조를 유지한다.

존재하지 않는 id 는 superadmin 과 그 밖의 사용자에게 서로 다른 이유로 거부된다. 권한 검사가 먼저 실행되는데 존재하지 않는 row 에는 부여된 권한도 없으므로, 그 검사를 통과하는 superadmin 만 대상을 찾을 수 없어 거부된다. 영구 삭제 절의 같은 시나리오도 마찬가지다.

이름 중복은 생성할 때와 수정할 때 서로 다른 에러로 거부된다. 생성은 이 엔티티 전용 에러로 거부하고, 수정은 저장소의 제약 위반 에러를 그대로 전파한다. 시나리오를 작성하기 전에 하나로 맞추는 방안에 대한 결정이 필요하다.

## 영구 삭제

이 adapter 에는 row 를 남기는 삭제가 없다.

## 여럿 영구 삭제

여럿 연산은 호출 전체를 거부하지 않는다. 처리한 종류는 처리된 목록에, 처리하지 못한 항목은 id 와 이유를 실패 목록에 담는다.
