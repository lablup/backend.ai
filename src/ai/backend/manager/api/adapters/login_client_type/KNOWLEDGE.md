# 로그인 클라이언트 종류 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 것과 실행 결과가 어긋나면 문장을 먼저
의심한다.

로그인 클라이언트 종류는 어느 스코프에도 속하지 않게 만들어진다. 만들기는 전역 역할이 지키고,
하나를 지목해 고치고 지우는 문은 그 종류에 걸린 권한이 지키는데 그 권한을 받을 길이 없다. 두
문 모두 슈퍼관리자만 지나지만 서로 다른 것으로 거부하고, 집행 스위치에는 뒤의 문만 반응한다.
읽기와 훑기는 인증만 본다.

## 만들기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이름만 주고 만든다 | 종류 없음, 전역 역할 있음 | 이름만 주고 만들기 | 설명이 빈 노드 |
| 이름과 설명을 함께 주고 만든다 | 종류 없음, 전역 역할 있음 | 이름과 설명으로 만들기 | 준 값이 그대로 실린 노드 |
| 이미 쓰이는 이름으로 만든다 | 그 이름의 종류가 있음, 전역 역할 있음 | 만들기 | 이름이 겹친다는 이유로 거부 |
| 슈퍼관리자가 아닌 사용자가 만든다 | 전역 역할 없음 | 만들기 | 역할로 거부 |
| 집행을 꺼도 슈퍼관리자가 아니면 못 만든다 | 엔티티 권한 집행 꺼짐, 전역 역할 없음 | 만들기 | 역할로 거부 |

이름이 비어 있거나 길이를 넘는 요청은 줄로 두지 않는다. 요청 타입이 이미 막는다.

## 읽기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 아무 권한도 받지 않은 사용자가 id로 읽는다 | 종류 하나, 아무 권한도 없음 | id로 조회 | 그 종류 전체 |
| 아무것도 갖지 않은 id로 읽는다 | 다른 종류만 있음 | id로 조회 | 대상 없음으로 거부 |

읽기에는 권한 문이 없다. 아무 권한도 받지 않은 사용자가 성공하는 줄이 그것을 증명하므로 이
절에는 거부 짝이 없고, 짝은 만들기 절의 역할로 거부되는 줄이다.

인증되지 않은 호출은 줄로 두지 않는다. 시나리오는 언제나 심은 사용자로 부른다.

## 훑기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 아무 권한도 받지 않은 사용자가 훑는다 | 종류 둘, 아무 권한도 없음 | 전체 조회 | 둘을 모두 센다 |
| 이름으로 걸러 훑는다 | 이름이 다른 종류 여럿 | 이름 필터 조회 | 그 이름의 것만 남는다 |
| 페이지 크기를 생략한다 | 종류 쉰하나 | 크기 없이 조회 | 쉰 건까지 오고 다음 쪽이 있다고 답한다 |

기본 페이지 크기가 다른 카탈로그의 열이 아니라 쉰이다. 셋째 줄이 그 수를 못박는다.

요청 타입이 커서를 받지만 이 훑기는 크기와 건너뛸 수만 읽는다. 커서를 함께 주면 지금은 조용히
버려진다. 줄을 적기 전에 버릴 것인지 쓸 것인지 정한다.

## 고치기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이름만 바꾼다 | 설명이 있는 종류 하나, 전역 역할 있음 | 이름 수정 | 이름은 새 값, 설명은 그대로 |
| 설명을 지운다 | 설명이 있는 종류, 전역 역할 있음 | 설명을 비우는 수정 | 설명이 없어진다 |
| 값을 하나도 주지 않는다 | 종류 하나, 전역 역할 있음 | 빈 수정 | 아무것도 바뀌지 않은 노드 |
| 이미 쓰이는 이름으로 바꾼다 | 종류 둘, 전역 역할 있음 | 한쪽 이름을 다른 쪽 이름으로 수정 | 이름이 겹친다는 이유로 거부 |
| 아무것도 갖지 않은 id를 고친다 | 다른 종류만 있음, 전역 역할 있음 | 이름 수정 | 대상 없음으로 거부 |
| 아무 권한도 받지 않은 사용자가 고친다 | 같은 종류, 아무 권한도 없음 | 이름 수정 | 권한 부족으로 거부 |
| 아무 권한도 받지 않은 사용자가 없는 id를 고친다 | 다른 종류만 있음, 아무 권한도 없음 | 이름 수정 | 권한 부족으로 거부 |
| 집행을 끄면 권한 없이도 고쳐진다 | 엔티티 권한 집행 꺼짐, 아무 권한도 없음 | 이름 수정 | 이름이 새 값인 노드 |

고치기는 지목할 id를 요청 밖에서 따로 받는다. 시나리오가 id를 두 곳에 적지 않도록 이 자리를
남긴다.

없는 id가 슈퍼관리자와 그렇지 않은 사람에게 다른 것으로 거부된다. 권한 검사가 먼저 도는데
없는 행에는 걸린 권한도 없으므로, 그 검사를 지나가는 슈퍼관리자만 대상 없음을 본다. 지우기
절의 같은 줄도 같다.

이름이 겹치는 거부는 만들 때와 고칠 때 다른 것으로 온다. 만들기는 이 엔티티의 말로 거부하고,
고치기는 저장소의 제약 위반을 그대로 낸다. 줄을 적기 전에 하나로 맞출 것인지 정한다.

## 지우기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 지운다 | 종류 하나, 전역 역할 있음 | 지우기 | 지운 id를 실은 답 |
| 아무것도 갖지 않은 id를 지운다 | 다른 종류만 있음, 전역 역할 있음 | 지우기 | 대상 없음으로 거부 |
| 아무 권한도 받지 않은 사용자가 지운다 | 같은 종류, 아무 권한도 없음 | 지우기 | 권한 부족으로 거부 |
| 집행을 끄면 권한 없이도 지워진다 | 엔티티 권한 집행 꺼짐, 아무 권한도 없음 | 지우기 | 지운 id를 실은 답 |

집행을 끄는 줄들이 만들기 절과 반대 결과를 갖는다. 고치기와 지우기의 문은 역할이 아니라 권한
그래프이므로 스위치가 통한다. 같은 스위치로 아무 권한 없는 사용자가 종류를 고치고 지울 수
있게 되지만 만들 수는 없다. 그것이 의도인지는 이 줄들을 실행해 본 뒤 정한다.

이 어댑터에는 soft delete가 없다.

## 아직 적지 않은 것

함께 세지만 적을 것이 없다.
