# domain adapter: 배경

규칙은 상위 디렉터리의 `AGENTS.md` 에 있다. 이 문서와 실행 결과가 어긋나면 문장을 먼저 의심한다.

도메인에는 권한 그래프로 권한을 줄 수 없다. 어느 스코프에도 속하지 않게 생성되고 자기 아래 하위 엔티티를 갖지 않는다. 그래서 생성과 스코프 없는 search 는 전역 superadmin 역할이 보호하고, 도메인 하나를 읽고 수정하는 호출은 권한 그래프가 보호한다. 두 호출이 서로 다른 이유로 거부하므로 짝을 따로 적는다. 권한을 받은 사용자가 나오는 곳은 자원 그룹 범위의 읽기뿐이다.

공통 계약(대상 존재, 여럿 구성, 페이지)은 프레임워크 계약 테스트가 확인한다. 이 문서에는 연산마다 대표 성공과 대표 실패, 그리고 도메인 규칙이 만드는 차이만 적는다.

## 생성

집행을 비활성화하는 시나리오가 따로 있는 이유는, 이 호출이 권한 그래프가 아니라 역할로 보호되어 집행 스위치와 무관하다는 것을 고정하기 위해서다.

생성은 자원 그룹을 연결하지 않는다. 연결은 자원 그룹 쪽 허용 목록 호출이 하고, 그 시나리오는 자원 그룹 adapter 문서에 있다.

레거시 GQL `CreateDomainNode` 와 `ModifyDomainNode` 는 도메인 생성 또는 수정과 자원 그룹 연결을 따로 호출한다. 연결이 실패하면 생성 또는 수정만 반영된 도메인이 남는다.

## 읽기

없는 대상과 권한 없음은 서로 다른 것으로 거부되어야 한다. 하나로 합치면 호출자가 어느 쪽으로 차단되었는지 알 수 없다.

## 여럿 읽기

여럿 읽기는 호출 전체를 거부하지 않고 항목마다 응답한다.

## 이름으로 id 찾기

두 호출 모두 인증만 확인한다. 권한은 그 id 를 받는 호출이 확인한다. 따라서 권한이 없어도 이름이 있는지는 드러나며, 설계상 허용한다. 다른 엔티티의 REST handler 와 GQL resolver 는 도메인 이름을 id 로 풀 때 이 호출을 먼저 호출한다. GQL 은 여럿 찾기를 이름에서 id 로 가는 로더로 사용해서 id 로 여럿 읽기에 잇는다.

## 수정

수정도 자원 그룹을 추가하거나 제거하지 않는다. 생성과 같이 자원 그룹 쪽 허용 목록 호출이 한다.

수정의 활성 플래그는 deprecated 다. 비활성화하면 삭제를, 활성화하면 복원을 호출하고, 이미 그 상태면 호출하지 않는다. 나머지 필드는 수정으로 반영한다. 상태는 노드에 담기지 않으므로 시나리오는 활성 플래그로 확인한다.

## 삭제, 복원, 영구 삭제

삭제와 복원은 현재 상태를 보지 않는다. 이미 그 상태여도 완료했다는 응답이 온다. 영구 삭제도 삭제되었는지를 보지 않는다. 연결된 것이 없으면 활성 도메인도 영구 삭제된다.

삭제는 활성 플래그를 비활성화하고 상태를 삭제로 변경한다. 복원은 둘을 되돌린다.

단건 수정, 삭제, 복원은 id 를 받는다. 이름을 받는 옛 REST 경로와 GQL mutation 은 이름으로 id 찾기를 먼저 호출하고 같은 호출로 잇는다. 이름을 받는 호출이 그 경로다. 영구 삭제는 이름을 받는다.

## 여럿 수정

여럿 수정은 항목마다 단건 수정과 같은 기준으로 삭제와 복원을 호출한다. 실패는 항목마다 실패 목록에 담는다.

## 여럿 삭제와 복원

여럿 연산은 호출 전체를 거부하지 않는다. 처리한 도메인은 처리된 목록에, 처리하지 못한 항목은 id 와 이유를 실패 목록에 담는다. 여럿 영구 삭제는 없다.

## search

## 자원 그룹 범위에서 search

자원 그룹 이름을 받는 GQL resolver 는 자원 그룹 adapter 의 이름으로 id 찾기를 먼저 호출하고, 얻은 id 를 범위로 전달한다. 도메인 adapter 는 자원 그룹 이름을 풀지 않는다.
