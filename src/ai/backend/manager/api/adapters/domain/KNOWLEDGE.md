# 도메인 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 것과 실행 결과가 어긋나면 문장을 먼저
의심한다.

도메인에는 권한을 걸 수 없다. 어느 스코프에도 속하지 않게 만들어지고 자기 아래 하위 엔티티를
갖지 않는다. 그래서 생성과 전체 조회는 전역 superadmin 역할이 지키고, 개별 도메인을 읽고
수정하는 문은 권한 그래프가 지킨다. 두 문이 서로 다른 것으로 거부하므로 짝을 따로 적는다.

## 만들기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이름과 설명만 주고 만든다 | 도메인 없음 | 만들기 | 요청에 없던 값이 기본값으로 채워진 노드 전체 |
| 슈퍼관리자가 아닌 사용자가 만들려 한다 | 권한 없음 | 만들기 | 역할로 거부 |
| 집행을 꺼도 슈퍼관리자가 아니면 못 만든다 | 엔티티 권한 집행 꺼짐 | 만들기 | 역할로 거부 |
| 이미 쓰이는 이름으로 만들려 한다 | 그 이름의 도메인이 있음 | 만들기 | 이름이 겹친다는 이유로 거부 |
| 이름이 공백뿐이다 | 도메인 없음 | 만들기 | 입력이 틀렸다는 이유로 거부 |

집행을 끄는 줄이 따로 있는 이유는, 이 문이 권한 그래프가 아니라 역할이라 집행 스위치와
무관하다는 것을 못박기 위해서다.

## 읽기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 이름으로 읽는다 | 그 이름의 도메인이 있음 | 이름으로 조회 | 그 도메인 |
| 아무 권한도 받지 않은 사용자가 읽는다 | 같은 도메인이 있음 | 이름으로 조회 | 권한 부족으로 거부 |
| 아무 도메인도 갖지 않은 이름으로 읽는다 | 다른 도메인만 있음 | 이름으로 조회 | 대상 없음으로 거부 |

없는 대상과 권한 없음이 서로 다른 것으로 거부되어야 한다. 하나로 뭉치면 어느 쪽으로 막혔는지
호출자가 알 수 없다.

| 슈퍼관리자가 활성 플래그를 내린다 | 활성 도메인이 있음 | 활성 플래그 수정 | 비활성 상태를 실은 답 |
| 아무 권한도 받지 않은 사용자가 수정한다 | 같은 도메인이 있음 | 설명 수정 | 권한 부족으로 거부 |
| 아무 도메인도 갖지 않은 이름을 수정한다 | 다른 도메인만 있음 | 설명 수정 | 대상 없음으로 거부 |
