# 클라이언트 IP 마스킹 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 내용과 실행 결과가 어긋나면 문장 쪽을 먼저
의심한다.

마스킹 정책은 대상마다 하나다. 대상은 셋 — 다른 대상이 물려받는 기본값, 로그인 이력, 감사
로그 — 이고, 대상을 키 삼아 등록하면 있던 행은 바뀌고 없던 행은 새로 생긴다(upsert). 그래서
생성 대신 등록이 있고, 하나를 읽는 호출은 없다. 등록과 검색은 전역 역할이 있어야 하고, 삭제만
그 정책에 부여된 권한을 검사하는데 그 권한을 받을 방법이 없다. 권한 검사 스위치는 삭제에만
영향을 준다.

## 등록

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 한 대상에 정책을 등록한다 | 정책 없음, 전역 역할 있음 | 대상·모드·두 접두 길이를 지정해 등록 | 지정한 값이 그대로 담긴 노드 |
| 접두 길이를 생략한다 | 정책 없음, 전역 역할 있음 | 대상과 모드만 지정해 등록 | 두 접두 길이가 비어 있는 노드 |
| 세 대상 각각에 등록한다 | 정책 없음, 전역 역할 있음 | 대상마다 하나씩 등록 | 셋이 모두 생긴다 |
| 세 모드 각각으로 등록한다 | 정책 없음, 전역 역할 있음 | 모드마다 하나씩 등록 | 지정한 모드가 그대로 담긴 노드 |
| 같은 대상에 다시 등록한다 | 그 대상의 정책 하나, 전역 역할 있음 | 다른 모드로 등록 | 같은 id의 행이 새 모드로 바뀐 노드 |
| 접두 길이를 생략하고 다시 등록한다 | 접두 길이가 있는 정책, 전역 역할 있음 | 대상과 모드만 지정해 등록 | 접두 길이가 비워진다 |
| 슈퍼관리자가 아닌 사용자가 등록한다 | 전역 역할 없음 | 등록 | 역할 부족으로 거부 |
| 모니터 역할이 등록한다 | 모니터 역할 | 등록 | 역할 부족으로 거부 |
| 권한 검사를 꺼도 슈퍼관리자가 아니면 등록할 수 없다 | 권한 검사 비활성화, 전역 역할 없음 | 등록 | 역할 부족으로 거부 |

등록은 기존 값과 병합하지 않는다. 있던 행을 지정한 값으로 통째로 바꾸므로 지정하지 않은 접두
길이는 사라진다. 부분 수정으로 오해하기 쉬운 동작이라 여섯 번째 시나리오를 따로 둔다.

비어 있는 접두 길이는 저장된 값이 없다는 뜻이고, 실제로 자를 때 쓰는 기본 폭은 마스킹하는 쪽이
정한다. 이 어댑터의 응답에는 빈 채로 온다.

접두 길이가 범위를 벗어나는 요청은 시나리오로 두지 않는다. 요청 타입이 이미 막기 때문이다.

## 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 검색한다 | 대상이 다른 정책 둘, 전역 역할 있음 | 전체 조회 | 둘 다 집계된다 |
| 대상 필터로 검색한다 | 세 대상의 정책, 전역 역할 있음 | 대상 필터 조회 | 그 대상의 정책 하나 |
| 모드 필터로 검색한다 | 모드가 다른 정책 여럿, 전역 역할 있음 | 모드 필터 조회 | 그 모드의 정책만 남는다 |
| 모니터 역할이 검색한다 | 정책 둘, 모니터 역할 | 전체 조회 | 슈퍼관리자와 같은 응답 |
| 슈퍼관리자가 아닌 사용자가 검색한다 | 전역 역할 없음 | 전체 조회 | 역할 부족으로 거부 |

대상이 셋뿐이라 정책도 셋을 넘지 못한다. 열 건을 넘겨 다음 페이지를 확인하는 시나리오는 만들 수
없으므로 두지 않는다.

모니터 역할은 전역 역할 검사에서 읽기만 통과한다. 검색의 모니터 시나리오와 등록의 모니터
시나리오가 그 차이를 보여 주는 짝이다.

## 삭제

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 삭제한다 | 정책 하나, 전역 역할 있음 | id로 삭제 | 삭제한 정책을 담은 응답 |
| 존재하지 않는 id를 삭제한다 | 다른 정책만 있음, 전역 역할 있음 | 삭제 | 대상을 찾을 수 없어 거부 |
| 아무 권한도 없는 사용자가 삭제한다 | 같은 정책, 아무 권한도 없음 | 삭제 | 권한 부족으로 거부 |
| 아무 권한도 없는 사용자가 없는 id를 삭제한다 | 다른 정책만 있음, 아무 권한도 없음 | 삭제 | 권한 부족으로 거부 |
| 권한 검사를 끄면 권한 없이도 삭제된다 | 권한 검사 비활성화, 아무 권한도 없음 | 삭제 | 삭제한 정책을 담은 응답 |

삭제만 id를 받는다. 등록은 대상으로 행을 찾고 삭제는 id로 찾으므로, 삭제할 id는 등록의 응답이나
검색 결과에서 읽는다. 하나를 읽는 호출이 없어 id를 알아도 그 행을 다시 확인하는 방법은
검색뿐이다.

존재하지 않는 id는 슈퍼관리자와 그 밖의 사용자에게 서로 다른 이유로 거부된다. 권한 검사가 먼저
실행되는데 없는 행에는 부여된 권한도 없으므로, 그 검사를 통과하는 슈퍼관리자만 "대상 없음"을
본다.

등록과 삭제는 서로 다른 검사를 거친다. 마지막 시나리오가 그 결과다 — 권한 검사를 끄면 아무
권한 없는 사용자가 정책을 삭제할 수는 있지만 등록할 수는 없다. 그것이 의도인지는 이 시나리오를
실행해 본 뒤 정한다.

이 어댑터에는 soft delete가 없다.

## 아직 적지 않은 것

없다. 어댑터가 제공하는 세 호출이 모두 위에 있다.

`batch_load_fields`는 모든 어댑터가 물려받는 공용 도우미이지 이 엔티티의 호출이 아니다. 레포트가
함께 세지만 적을 것이 없다.
