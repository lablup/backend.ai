# 클라이언트 IP 마스킹 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 것과 실행 결과가 어긋나면 문장을 먼저
의심한다.

마스킹 정책은 대상마다 하나다. 대상은 셋 — 다른 대상이 물려받는 기본값, 로그인 이력, 감사
로그 — 이고, 대상을 이름 삼아 넣으면 있던 행이 바뀌고 없던 행이 생긴다. 그래서 만들기 대신
넣기가 있고, 하나를 읽는 호출은 없다. 넣기와 훑기는 전역 역할이 지키고, 지우기만 그 정책에
걸린 권한이 지키는데 그 권한을 받을 길이 없다. 집행 스위치는 지우기에만 통한다.

## 넣기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 한 대상에 정책을 넣는다 | 정책 없음, 전역 역할 있음 | 대상·모드·두 접두 길이로 넣기 | 준 값이 그대로 실린 노드 |
| 접두 길이를 생략한다 | 정책 없음, 전역 역할 있음 | 대상과 모드만 주고 넣기 | 두 접두 길이가 빈 노드 |
| 세 대상 각각에 넣는다 | 정책 없음, 전역 역할 있음 | 대상마다 하나씩 넣기 | 셋이 모두 생긴다 |
| 세 모드 각각으로 넣는다 | 정책 없음, 전역 역할 있음 | 모드마다 하나씩 넣기 | 준 모드가 그대로 실린 노드 |
| 같은 대상에 다시 넣는다 | 그 대상의 정책 하나, 전역 역할 있음 | 다른 모드로 넣기 | 같은 id의 행이 새 모드로 바뀐 노드 |
| 접두 길이를 빼고 다시 넣는다 | 접두 길이가 있는 정책, 전역 역할 있음 | 대상과 모드만 주고 넣기 | 접두 길이가 비워진다 |
| 슈퍼관리자가 아닌 사용자가 넣는다 | 전역 역할 없음 | 넣기 | 역할로 거부 |
| 모니터 역할이 넣는다 | 모니터 역할 | 넣기 | 역할로 거부 |
| 집행을 꺼도 슈퍼관리자가 아니면 못 넣는다 | 엔티티 권한 집행 꺼짐, 전역 역할 없음 | 넣기 | 역할로 거부 |

넣기는 합치지 않는다. 있던 행을 준 값으로 통째로 바꾸므로 주지 않은 접두 길이는 사라진다.
부분 수정으로 읽히기 쉬운 자리라 여섯째 줄을 따로 둔다.

빈 접두 길이는 저장된 값이 없다는 뜻이고, 실제로 자를 때 쓰는 기본 폭은 마스킹하는 쪽이
정한다. 이 어댑터의 답에는 빈 채로 온다.

접두 길이가 범위를 벗어나는 요청은 줄로 두지 않는다. 요청 타입이 이미 막는다.

## 훑기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 훑는다 | 대상이 다른 정책 둘, 전역 역할 있음 | 전체 조회 | 둘을 모두 센다 |
| 대상으로 걸러 훑는다 | 세 대상의 정책, 전역 역할 있음 | 대상 필터 조회 | 그 대상의 것 하나 |
| 모드로 걸러 훑는다 | 모드가 다른 정책 여럿, 전역 역할 있음 | 모드 필터 조회 | 그 모드의 것만 남는다 |
| 모니터 역할이 훑는다 | 정책 둘, 모니터 역할 | 전체 조회 | 슈퍼관리자와 같은 답 |
| 슈퍼관리자가 아닌 사용자가 훑는다 | 전역 역할 없음 | 전체 조회 | 역할로 거부 |

대상이 셋뿐이라 정책도 셋을 넘지 못한다. 열 건을 넘겨 다음 쪽을 보는 줄은 세울 수 없으므로
두지 않는다.

모니터 역할은 전역 역할 문의 읽기만 지난다. 훑기의 이 줄과 넣기의 모니터 줄이 그 갈림을 보이는
짝이다.

## 지우기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 지운다 | 정책 하나, 전역 역할 있음 | id로 지우기 | 지운 정책을 실은 답 |
| 아무것도 갖지 않은 id를 지운다 | 다른 정책만 있음, 전역 역할 있음 | 지우기 | 대상 없음으로 거부 |
| 아무 권한도 받지 않은 사용자가 지운다 | 같은 정책, 아무 권한도 없음 | 지우기 | 권한 부족으로 거부 |
| 아무 권한도 받지 않은 사용자가 없는 id를 지운다 | 다른 정책만 있음, 아무 권한도 없음 | 지우기 | 권한 부족으로 거부 |
| 집행을 끄면 권한 없이도 지워진다 | 엔티티 권한 집행 꺼짐, 아무 권한도 없음 | 지우기 | 지운 정책을 실은 답 |

지우기만 id를 받는다. 넣기는 대상으로 행을 찾고 지우기는 id로 찾으므로, 지울 id는 넣기의
답이나 훑기에서 읽는다. 하나를 읽는 호출이 없어 id를 쥐고도 그 행을 다시 보는 길은 훑기뿐이다.

없는 id가 슈퍼관리자와 그렇지 않은 사람에게 다른 것으로 거부된다. 권한 검사가 먼저 도는데
없는 행에는 걸린 권한도 없으므로, 그 검사를 지나가는 슈퍼관리자만 대상 없음을 본다.

넣기와 지우기가 서로 다른 문을 지난다. 마지막 줄이 그 결과다 — 집행을 끄면 아무 권한 없는
사용자가 정책을 지울 수 있지만 넣을 수는 없다. 그것이 의도인지는 이 줄을 실행해 본 뒤 정한다.

이 어댑터에는 soft delete가 없다.

## 아직 적지 않은 것

없다. 어댑터가 내놓는 세 호출이 모두 위에 있다.

`batch_load_fields`는 모든 어댑터가 물려받는 공용 도우미이지 이 엔티티의 호출이 아니다. 레포트가
함께 세지만 적을 것이 없다.
