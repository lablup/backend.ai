# audit_log adapter: 배경

규칙은 상위 디렉터리의 `AGENTS.md` 에 있다. 이 문서와 실행 결과가 어긋나면 문장을 먼저 의심한다.

`audit_log` 엔티티는 소유자가 고정되지 않는다. 동작이 실행될 때마다 그 동작이 다룬 엔티티를 대상으로 row 가 하나씩 자동으로 기록되므로 기록마다 소유자가 다르고, 전역 동작의 기록에는 소유자가 없다. 그래서 이 adapter 에는 쓰기가 없고 스코프 없는 검색, 여러 id 조회, 범위 지정 검색, 기록 하나의 범위 검색만 있다. 시나리오가 전제하는 기록은 adapter 로 만들 수 없으므로 기록을 남기는 쓰기 경로로 직접 미리 저장한다.

권한 검사 방식은 셋이다. 스코프 없는 검색은 호출한 사용자가 superadmin 인지 검사하고, 읽기이므로 monitor 역할 사용자도 통과한다. 범위 지정 검색은 지정한 엔티티마다 부여된 읽기 권한을 검사하고, 하나라도 볼 수 없으면 요청 전체를 거부한다. 여러 id 조회와 기록 하나의 범위 검색은 기록의 소유자 중 하나라도 읽을 수 있는지를 기록마다 검사한다. 기록의 소유자는 기록이 대상으로 한 엔티티, 기록에 남은 범위 엔티티, 기록을 실행한 사용자다. 거부 이유가 방식마다 다르므로 짝이 되는 시나리오를 따로 적는다.

범위를 지정하는 방법은 둘이다. 기록의 대상 엔티티로 지정하거나, 기록의 `triggered_by` 사용자로 지정한다. 엔티티로 지정하면 그 엔티티에 부여된 권한을, 사용자로 지정하면 그 사용자에 부여된 권한을 검사한다.

## 전체 검색

"monitor 역할 사용자가 검색한다"는 전체 검색이 읽기에 한해 monitor 역할 사용자를 통과시킨다는 것을 확인한다. "monitor 역할 사용자가 권한 없이 조회한다", "monitor 역할 사용자가 권한 없이 지정해 검색한다"와 짝이고 결과가 반대다.

응답의 `client_ip` 값은 기록될 때 마스킹 정책을 거친 값을 그대로 담는다. 조회할 때 다시 마스킹하지 않으므로, 정책이 어떤 값을 남기는지는 마스킹 정책 문서가 다룬다.

## 여러 id 조회

id 마다 그 기록의 소유자 중 하나라도 읽을 수 있는지 검사하고, 항목마다 따로 응답한다. 볼 수 없는 기록은 그 항목만 거부되고 나머지는 반환된다. 범위 지정 검색과 달리 부분 성공이 있다.

기록의 대상 엔티티를 읽을 수 없어도 기록이 남긴 범위나 기록을 실행한 사용자를 통해 읽을 수 있다. 범위 지정 검색에서 그 기록이 보이는 조건과 같다.

없는 id 는 누가 조회하든 빈 항목이다. 참조하는 엔티티가 없으므로 권한을 검사할 대상이 없다.

monitor 역할 사용자는 여기서 통과하지 않는다. 전체 검색과 달리 이 조회는 권한 그래프를 검사한다.

## 범위 지정 검색

부분 성공은 없다. 지정한 엔티티 전체를 검색 전에 인가하므로, 볼 수 없는 엔티티가 하나라도 있으면 나머지를 반환하는 대신 요청 전체를 거부한다. 항목마다 따로 응답하는 여러 id 조회와 다르므로 "볼 수 없는 엔티티가 하나라도 섞이면 전체가 거부된다"를 따로 둔다.

엔티티를 지정하면 그 엔티티를 대상으로 한 기록과 그 엔티티를 범위로 삼아 실행된 동작의 기록이 함께 반환된다. 프로젝트를 지정하면 그 프로젝트 안에서 실행된 동작의 기록도 함께 반환된다는 뜻이고, "지정한 엔티티 안에서 실행된 동작의 기록도 반환된다"가 이를 확인한다.

자기 기록만 조회하는 호출은 따로 없다. 자기가 실행한 기록도 호출자 자신의 사용자 엔티티에 부여된 읽기 권한으로 조회하므로, 그 권한이 없으면 자기 기록도 볼 수 없다.

monitor 역할로 통과하는 검사는 superadmin 검사뿐이다. 범위 지정 검색은 권한 그래프를 검사하므로 monitor 역할 사용자도 권한을 받아야 한다.

지정한 엔티티가 실제로 있는지는 따로 확인하지 않는다. 권한 검사가 먼저 실행되고 없는 엔티티에는 아무도 권한을 갖지 않는다. 대상을 찾을 수 없어 거부되는 경우가 아니다. superadmin 은 그 검사를 지나가므로 없는 엔티티를 지정해도 거부되지 않고 검색이 실행되어 빈 페이지가 온다.

아무것도 지정하지 않은 요청은 시나리오로 두지 않는다. 요청 타입이 이미 거부하므로 adapter 가 보장하는 동작이 아니다.

## 기록 하나의 범위 검색

기록을 읽을 수 있으면 그 기록의 범위를 모두 읽는다. 범위 하나를 통해 기록에 접근했더라도 그 기록에 남은 다른 범위까지 반환된다. 범위 row 에는 권한 검사가 따로 없다.

권한은 여러 id 조회와 같은 기준으로 검사한다. 기록 하나만 지정하므로 부분 성공은 없고, 소유자 중 아무것도 읽을 수 없으면 요청이 거부된다.

monitor 역할 사용자는 여기서 통과하지 않는다. 전체 검색과 달리 이 검색은 권한 그래프를 검사한다.
