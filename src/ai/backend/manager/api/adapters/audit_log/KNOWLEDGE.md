# 감사 기록 어댑터 — 시나리오

규칙은 상위 디렉터리의 `AGENTS.md`에 있다. 여기 적힌 것과 실행 결과가 어긋나면 문장을 먼저
의심한다.

감사 기록은 소유자가 고정되지 않은 필드다. 동작이 돌 때마다 그 동작이 건드린 엔티티 이름으로
한 행씩 자동으로 남으므로, 기록마다 소유자가 다르고 전역 동작의 기록은 소유자가 없다. 그래서
이 어댑터에는 쓰기가 없고 읽기 셋뿐이다. 시나리오가 전제로 두는 기록은 어댑터로 만들 수
없으므로, 기록을 남기는 쓰기 경로로 직접 심는다.

문은 둘이다. 전체 검색과 여러 id 읽기는 전역 superadmin 역할이 지키고, 읽기이므로 모니터
역할도 통과한다. 지목 검색은 지목한 엔티티마다 걸린 읽기 권한이 지키고, 하나라도 볼 수
없으면 요청 전체를 거부한다. 두 문이 서로 다른 이유로 거부하므로 짝을 따로 적는다.

지목하는 방법이 둘이다. 기록의 대상 엔티티로 지목하거나, 기록을 일으킨 사용자로 지목한다.
권한은 앞은 그 엔티티에, 뒤는 그 사용자에 묻는다.

## 전체 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 슈퍼관리자가 필터 없이 검색한다 | 서로 다른 엔티티의 기록 둘 | 전체 검색 | 둘 다 오고, 최근 것이 먼저다 |
| 모니터 역할 사용자가 검색한다 | 같은 기록 둘, 모니터 역할 | 전체 검색 | 슈퍼관리자와 같은 답 |
| 슈퍼관리자가 아닌 사용자가 검색한다 | 기록 하나, 권한 없음 | 전체 검색 | 역할 부족으로 거부 |
| 권한 집행을 꺼도 슈퍼관리자가 아니면 검색할 수 없다 | 권한 집행 꺼짐, 권한 없음 | 전체 검색 | 역할 부족으로 거부 |
| 페이지 크기를 생략한다 | 기록 열하나 | 크기 없이 검색 | 열 건이 오고 다음 페이지가 있다고 답한다 |
| 상태로 걸러 검색한다 | 성공 기록과 거부 기록이 섞여 있음 | 상태 필터로 검색 | 고른 상태의 기록만 온다 |
| 일으킨 사용자로 걸러 검색한다 | 두 사용자가 남긴 기록이 하나씩 | 사용자 필터로 검색 | 그 사용자가 일으킨 기록만 온다 |
| 페이지 방식을 둘 섞어 준다 | 기록 하나 | 오프셋 방식과 커서 방식을 함께 주고 검색 | 입력이 틀렸다는 이유로 거부 |
| 커서 값이 깨져 있다 | 기록 하나 | 해석할 수 없는 커서로 검색 | 커서가 틀렸다는 이유로 거부 |

모니터 행은 이 문이 읽기에 한해 모니터 역할을 통과시킨다는 것을 못박는다. 지목 검색의
모니터 행과 짝이고 결과가 반대다.

집행을 끄는 행은 이 문이 권한 그래프가 아니라 역할을 보므로 집행 스위치와 무관하다는 것을
못박는다. 지목 검색의 같은 행과 결과가 반대다.

요청 타입은 대상 엔티티 id 필터를 받지만 어댑터가 쓰지 않는다. 지금은 조용히 버려진다. 행을
적기 전에 버릴지 쓸지 정한다.

답의 클라이언트 주소는 기록될 때 마스킹 정책을 거친 값 그대로다. 읽을 때 다시 가리지
않으므로, 정책이 무엇을 남기는지는 마스킹 정책 쪽 시나리오가 본다.

## 여러 id로 읽기

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 있는 id와 없는 id를 섞어 읽는다 | 기록 둘 | 있는 id 둘과 없는 id 하나를 한 번에 | 준 순서대로 오고, 없는 id 자리는 비어 있다 |
| 빈 목록을 준다 | 기록 하나 | 빈 id 목록 | 빈 답. 문도 지나지 않는다 |
| 모니터 역할 사용자가 읽는다 | 기록 둘, 모니터 역할 | id 둘을 한 번에 | 슈퍼관리자와 같은 답 |
| 슈퍼관리자가 아닌 사용자가 읽는다 | 기록 둘, 권한 없음 | id 둘을 한 번에 | 역할 부족으로 거부 |

id마다 따로 답하는 모양이지만 실제로는 전체 검색을 id 조건으로 부른다. 그래서 권한이 없으면
id별로 갈리지 않고 요청 전체가 거부된다.

## 지목 검색

| 시나리오 | 상황 | 요청 | 결과 |
|---|---|---|---|
| 읽기 권한을 받은 사용자가 엔티티를 지목해 검색한다 | 엔티티 둘에 기록이 하나씩, 한쪽에만 읽기 권한 있음 | 권한 있는 엔티티를 지목해 검색 | 그 엔티티의 기록만 온다 |
| 지목한 엔티티 안에서 돈 동작의 기록도 온다 | 프로젝트 하나, 그 프로젝트를 스코프로 돈 동작의 기록, 프로젝트에 읽기 권한 있음 | 그 프로젝트를 지목해 검색 | 그 기록이 온다 |
| 일으킨 사용자로 지목해 검색한다 | 두 사용자가 남긴 기록이 하나씩, 한 사용자에 읽기 권한 있음 | 그 사용자를 일으킨 사용자로 지목해 검색 | 대상이 무엇이든 그 사용자가 일으킨 기록만 온다 |
| 엔티티 여럿을 지목하면 합쳐서 온다 | 엔티티 둘에 기록이 하나씩, 둘 다 읽기 권한 있음 | 둘을 함께 지목해 검색 | 두 기록이 다 오고, 최근 것이 먼저다 |
| 지목한 범위 안에서 필터가 걸린다 | 한 엔티티에 성공 기록과 거부 기록, 읽기 권한 있음 | 그 엔티티를 지목하고 상태 필터로 검색 | 고른 상태의 기록만 온다 |
| 페이지 크기를 생략한다 | 한 엔티티에 기록 열하나, 읽기 권한 있음 | 크기 없이 검색 | 열 건이 오고 다음 페이지가 있다고 답한다 |
| 볼 수 없는 엔티티가 하나라도 섞이면 전부 거부된다 | 엔티티 둘에 기록이 하나씩, 한쪽에만 읽기 권한 있음 | 둘을 함께 지목해 검색 | 권한 부족으로 거부 |
| 읽기 권한이 없는 사용자가 지목해 검색한다 | 엔티티 하나에 기록 하나, 권한 없음 | 그 엔티티를 지목해 검색 | 권한 부족으로 거부 |
| 모니터 역할 사용자가 권한 없이 지목해 검색한다 | 같은 기록, 모니터 역할, 권한 없음 | 그 엔티티를 지목해 검색 | 권한 부족으로 거부 |
| 권한 없이 자기가 일으킨 기록을 검색한다 | 부르는 사용자가 남긴 기록, 자기 자신에 읽기 권한 없음 | 자기를 일으킨 사용자로 지목해 검색 | 권한 부족으로 거부 |
| 없는 엔티티를 지목한다 | 다른 엔티티에 읽기 권한 있음 | 어느 엔티티도 아닌 id를 지목해 검색 | 권한 부족으로 거부 |
| 슈퍼관리자가 없는 엔티티를 지목한다 | 슈퍼관리자 | 어느 엔티티도 아닌 id를 지목해 검색 | 빈 답 |
| 권한 집행을 끄면 권한 없이도 지목한 기록을 검색한다 | 권한 집행 꺼짐, 권한 없음 | 그 엔티티를 지목해 검색 | 그 엔티티의 기록이 온다 |
| 엔티티 id가 id 형식이 아니다 | 읽기 권한 있음 | id 자리에 임의의 문자열을 넣고 검색 | 입력이 틀렸다는 이유로 거부 |

부분 성공은 없다. 지목한 엔티티 전부를 검색 전에 인가하므로, 볼 수 없는 엔티티가 하나라도
있으면 나머지를 주는 대신 요청 전체를 거부한다. 엔티티마다 따로 답하는 다른 읽기와 다르므로
일곱째 행을 따로 둔다.

엔티티를 지목하면 두 종류의 기록이 온다. 그 엔티티를 대상으로 한 기록과, 그 엔티티를
스코프로 삼아 돈 동작의 기록이다. 프로젝트를 지목하면 그 프로젝트 안에서 돈 동작이 함께
온다는 뜻이고, 둘째 행이 그것을 본다.

자기 기록을 읽는 문이 따로 없다. 자기가 일으킨 기록도 자기 사용자 엔티티에 걸린 읽기
권한으로 읽으므로, 그 권한이 없으면 자기 기록도 볼 수 없다.

모니터 역할이 통과하는 것은 역할 문뿐이다. 지목 검색은 권한 그래프를 보므로 모니터도 권한을
받아야 한다.

지목한 엔티티가 실제로 있는지는 보지 않는다. 권한 검사가 먼저 도는데 없는 엔티티에는 걸린
권한도 없으므로, 그 검사를 건너뛰는 슈퍼관리자만 빈 답을 본다. 대상 없음으로 거부하는
자리가 아니다.

아무것도 지목하지 않은 요청은 행으로 두지 않는다. 요청 타입이 이미 막으므로 어댑터가
보장하는 것이 아니다.

## 아직 적지 않은 것

어느 시나리오도 부르지 않는 어댑터 호출은 없다. 호출 셋이 모두 위에 있다.

기록을 CSV로 내보내는 읽기는 이 어댑터에 없다. 내보내기 REST 핸들러가 서비스를 직접
부르므로, 그쪽에 어댑터가 생기면 그 문서에 적는다.

거부된 검색도 지목한 엔티티마다 거부 기록으로 남는다. 기록을 쓰는 쪽의 보장이므로 어댑터
시나리오로 두지 않는다.
